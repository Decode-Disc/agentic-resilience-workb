## Confirmed causes and bounded next work

### Silent scope replacement

In `insufficient-dated-support/requests-1.json`, accepted adjustment `rd7fnv0spmdmhzjfdhgqk30nxh8jhgbh` contains the explicit estimate-review scope but an open event basis without `activityExcerpt`. `agent-saved-framing.json` instead contains “Investigate the resilience of CCC Intelligent Solutions Holdings Inc. in its core operating workflows while the event is being clarified.” The initial scope was blank. This input/output matches `prepareProvisionalFraming` in the frozen `code/convex/domain/framingProvenance.ts`: absent excerpt plus blank current scope unconditionally selects the company-level fallback, even when the incoming scope is nonempty.

This is a confirmed harness transformation, not model refusal or retrieval failure. Correct the existing provisional-framing owner so a nonempty narrow proposal either retains authorized scope or receives an actionable missing-anchor refusal. Regression: submit the retained undated proposal through the real framing operation and assert that the stored scope cannot silently broaden. No new semantic classifier is required to reject that silent transformation.

### Mislocated validation and lost public associations

The independent-scrutiny proposal cites `rd7dj26trpc384127wn8jgysz`, while the adopted trade reading is `rd7dj26trpc384127wn8jgrh5n8jgysz`. Its retained invalid request (`rd79vkcrshtye65qycq3xw1mws8jhv3n`) reports `eventBasis.kind` and expects `none | open | analyst | public`, although the input already says `open`. The installed `convex-helpers` union validator retains the last failing branch error, and `operationInputFeedback` describes that reported path rather than locating the matching discriminated branch. This source mechanism explains the observed misleading feedback; no claim that open bases are unsupported is justified.

The subsequent model response explicitly suspects the open variant and changes to an analyst basis. Accepted request `rd7bkqmch03z4q90t5hkkpt3kn8jhmr9` retains useful question text but no public read associations. Thus the first defect is a model-generated identifier error, compounded by harness feedback and permissive alternative provenance. Correct nested-field diagnostics in the existing invocation-validation owner and regression-test the malformed public read reference through native correction. Recovery must correct the identifier and retain the public associations, rather than obtain success by relabelling the evidence as analyst intent. The provisional reviewer left this localization open; this paragraph records the later developer trace.

### Event relevance and source attribution

First-party depth's rejected and accepted adjustments contain the same named Reinspection hypothesis. The second proposal corrects exactly the scope anchor named by the refusal; the targeted diagnostic works, but it cannot repair the unrelated semantic error. That launch was only a discovery lead, while its condition used `basis.kind: analyst` with the generic original question. Balanced likewise adds unsupported acquirer names to a hypothesis citing a limited adopted passage. The actual continuation and retained instructions were available; the evidence does not support lost context as the cause.

These are demonstrated model proposal/selection errors accepted by validators that check provenance structure rather than semantic entailment. Preserve the distinction: do not treat a successful save or oriented search suffix as proof of relevance. Retain these cases for a bounded design decision at framing proposal/adoption: named event hypotheses need appropriate adopted support, common workflow checks remain unconditional, and unavailable event identity remains explicit. Determine how that rule should be enforced before adding a semantic gate or broad prompt changes. The independent-scrutiny case demonstrates improved source-family selection in one run, not general preset reliability.
