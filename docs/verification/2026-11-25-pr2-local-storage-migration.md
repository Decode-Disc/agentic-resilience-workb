# Local storage migration verification

The local deployment `local-aboul_panga-dd_proto` was migrated from the existing November 25 backup using PR 2's additive handlers at `7ea7634e125701c00369f58b2b6f4ba83f9a6b93` and the conversation migration admission correction described below. This record establishes local data preservation and bounded public history reads. The local component retirement described below has since completed. Remaining whole-body API retirement, final runtime capacity measurements and final CI are still pending.

## Backup and migration

The original export is 179,396,336 bytes with SHA-256 `997170d405b4d704ffc82736b7a1346afef022a42b3fd9a1c9fdd808770bb01c`. Its checksum was recomputed and matched. The original stopped-backend raw backup is also retained, at 1,619,221,490 bytes. Both were preserved by hard link before this migration; no restore or database reset was performed. Private scripts, inventories and checkpoint evidence are retained in the operator's local runtime directory and are not published with this report.

All 99 legacy conversation scopes were copied, verified, reconciled and reopened: 288 original deliveries and 96 completed mission rows were reconciled. The database now contains 108 conversations and 313 deliveries; none is frozen and no legacy delivery lacks its retained body reference. All 31 original active-turn documents, conversation pointers and queue counts matched the backup after migration. Provider-call count remained 833; no provider generation was requested by this work.

An active turn previously blocked migration even when it had no possible writer. Migration now requires a global publication hold, matching conversation/run/mission/turn ownership, a Pi Durable backend, no active writer and no live session lease. It preserves logical turn and mission status. Eighteen registered Convex tests passed, covering blocked and running quiescent turns, a later queued request, active lease/writer refusal, foreign correlation, frozen writer admission and exact body restoration. The blanket active-turn refusal and four missing ownership checks were reproduced before correction. The corrected handlers were published successfully by the existing local watcher at 18:27 on November 25.

## Integrity and public reads

Independent Node and native WebCrypto checks matched 49,540 original records across invocation, execution-event, provider-call, source, capture, search-passage, proposal/rebuild/item, task-result and review-item tables. The six largest tables used 187 independently hashed creation-time blocks rather than a single aggregate transaction. These checks establish preservation, not reduced query cost. The initial execution-event comparison preceded a subsequent backfill of 413 derived context-history hashes; that backfill does not establish whole-row byte equality afterward and did not replace original observation text.

Both authenticated public history APIs were exercised on two existing research conversations. Forty-six unique original messages were reconstructed through the body reader with exact offsets, lengths and SHA-256 hashes matching the component source. Conversation history returned 44 and 2 messages; Workbench history returned 42 and 2 because it omits two approval receipts. The saved expected hashes permit repeating these reads after component removal without using a legacy reader.

The component inventory independently matched the backup: 522 threads, 2,119 messages and a largest stored message document of 28,458 JSON bytes. Related embedding, file, memory and stream tables were empty. There are 107 threads with current application references and 415 without one. The latter retain known visitor identities and historical producer patterns, but no reason for the former application parents' absence is asserted. No component rows have been deleted at this checkpoint.

## Execution limits and next acceptance boundary

One migration step timed out while concurrent verification was running. It resumed through the existing checkpoint and completed without raising resource limits; the underlying local platform timeout was not established. An earlier administrative verification script supplied an incomplete identity and was corrected to the installed CLI's subject, issuer and token-identifier shape; application authorization was unchanged. The maintenance hold was released after migration and public-read checks; no active worker or live nonterminal grant was observed at release.

Local reconciliation does not establish post-retirement functionality, peak action-memory safety, full retained Sources context cost, semantic research quality or deployment-wide acceptance elsewhere. The next acceptance boundary is the approved removal of verified obsolete copies and executable compatibility code, followed by component-absent history, native recovery, approvals, Sources wording and resource checks on the final implementation.

## Component retirement

After the pre-retirement checks, 288 delivery source references, 99 conversation source/checkpoint records, 93 obsolete textual result encodings and the stream-upgrade control were cleared through a temporary owner-checked internal command. A deliberately mismatched body digest was refused before any patch. All 481 intended transitions completed through a durable operator checkpoint. Three older simulated approval fixtures already had a published delivery without a mission result; they were preserved without inventing a completion result. Historical non-conversation result storage remains a separate contract.

The component inventory was checked again immediately before deletion and still matched the original backup. The operator deleted one message per mutation, including the largest 28,458-byte stored document, with no embeddings, files or streams present. After the first committed deletion, an immediate retry returned no deleted identity; the operator then exited and resumed from its saved checkpoint. All 2,119 original messages and 522 threads were removed. An independent one-row query of every component table confirmed all 18 tables empty. The original archived component bytes remain in the verified backup; immutable generation provenance references were not rewritten.

Component registration, the exact `@convex-dev/agent` 0.7.9 dependency, runtime message decoders, copy/reconciliation handlers, source fields and temporary stream-upgrade protocol were removed. The installed publisher regenerated declarations and unmounted the component successfully. Both authenticated public histories were then re-read against saved pre-retirement hashes without invoking a legacy reader: all 46 original messages still matched. This was administrative API verification with the existing owner identities; it does not substitute for browser admission checks.

Stream finalization now requires the manifest maintained by append and reads only its tail. A regression first demonstrated the removed implementation reconstructing an absent packed manifest; the final implementation refuses it without modifying the record. The journal and one-shot suites passed 29 tests, including exact sealing of an 18,432,008-byte stream below 32 KiB of measured emulator reads. Transition-only migration regressions are preserved outside the build; the native recovery suite retains comparisons with archived original prose while exercising the final retained representation.

The component-absent battery passed 82 tests across eight suites covering current conversation/history, native recovery, commands, approvals, original Sources wording and dossier purge. An isolated Chromium journey subsequently passed in 2.1 minutes including setup: four persisted native invocations, the expected three documentary operations, one completion, no provider calls and an unchanged snapshot after reload. The preceding run overlapped the regression battery and cold Vite startup and exceeded its unchanged 90-second completion poll. Its trace shows all three operations succeeding and the final continuation ready at 83.6 seconds, followed by teardown cancellation at 92.4 seconds. The isolated pass does not establish a root-cause latency fix. Remaining aggregate APIs and real retained-context/action-memory measurements were not yet complete when this section was written. No claim of reduced Sources context cost or full TDD acceptance follows from component removal alone.

The recovered database contains 26 current Sources preparation records, including their retained capture and qualification references. That discovery supersedes the earlier absence of a full supplied archive; it does not establish that a current authorized mission context can be reconstructed for every historical preparation. The largest retained preparation by documentary work has 18 work entries, two captures and two qualification records. Read-cost and authority checks still need to be run rather than inferred from the inventory.
