# Source action grouping and concurrency measurement

Grouping capture inspection and qualification into one durable action per source reduces warm native replay median time at concurrency 2 from 44.829 s to 28.747 s, saving 16.082 s (35.9%). All sixteen replay proposals have identical normalized business fields and no provider calls. Four subsequently authorized fresh qualification runs show an observed 20.8% median time reduction at concurrency 4, with equal input hashes but more contradictory contribution scopes. Four comparison runs on one common fresh qualification reference show a 21.9% median reduction and exactly seven calls for seven sources per run. These single-corpus results do not establish general quality acceptance at concurrency 4.

Every response reports the same system fingerprint: `vllm-0.31.1rc1.dev273+g2eb491e18-tp2-dd47e93f`. Its source revision resolves to public vLLM commit `2eb491e18b1ce5b8a25e4c88f32dbb5d028d525c`. That commit's [reproducibility documentation](https://github.com/vllm-project/vllm/blob/2eb491e18b1ce5b8a25e4c88f32dbb5d028d525c/docs/usage/reproducibility.md) distinguishes default serving from batch-invariant operation; its [batch-invariance documentation](https://github.com/vllm-project/vllm/blob/2eb491e18b1ce5b8a25e4c88f32dbb5d028d525c/docs/features/batch_invariance.md) describes numerical behavior that otherwise depends on batch size and scheduling, including tensor-parallel reductions. This is a supported explanation for the observed provider-side sensitivity, not proof of Relace's exact kernels or environment flags. The returned fingerprint does not expose those flags. The current official route metadata advertises no seed support; adding an unsupported seed is not a demonstrated remedy.

The confirmed failure chain is concrete: the model emits useful positive contributions and an excessively broad `no_substantive_content` scope; the response schema accepts both fields independently; materialization copies the scope unchanged; restriction validation checks scope presence and inspected passage identities without reconciling the positive and negative decisions; `sourceFindingUsage` then applies the document-wide conflict guard to every contribution. The guard preserves the source and prevents unsupported use, but cannot recover the intended narrower scope from the model's explanation. The example explanation names missing financial/commercial/security roles while the formal scope says the entire independent-research document has no substantive content. The application does not invent the broad scope during scheduling, materialization or persistence.

The architectural weakness is two independently generated representations of absence: null contributions for missing roles and a separate global negative restriction capable of contradicting all positive contributions. Retaining concurrency 2 reduces observed exposure in this sample but does not correct the defect, which also occurs at 2. The next correction should extend the existing qualification-contract owner to enforce cross-field consistency and reduce that redundant semantic authority, with protocol/cache versioning and historical read compatibility. It must preserve genuine uncertainty, explicit scoped conflicts and the source itself. No extra verifier call per source, new workflow engine or silent rewriting of recorded restrictions is required by this diagnosis. Provider reproducibility remains a separate route-quality condition; the application must not rely on temperature zero as a consistency guarantee.

This is a completed diagnosis and a correction recommendation, not an implemented repair. The original minimal replay remains red. No application tests, deployment sync or browser gate is claimed for a nonexistent production change; executed checks are the recorded replay/minimization, actual-adapter offline probes, authorization guard, immutable code/request audit and the approved 24-call provider experiment.
