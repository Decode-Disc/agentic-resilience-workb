# Workbench qualification protocol stabilization — 2026-11-03

This is one unpaid tooling correction batch. No new application behavior, model routing, provider activation, paid lot or process-crash scenario was introduced. Earlier immutable qualification records remain separate; their successful mission counts are not retroactively treated as task-quality acceptance.

The retained version-2 protocol now freezes the actual ten-case browser manifest, its unchanged requests, declared material expectations, profile eligibility and candidate source identity. The separate four-case conversation-history reference is listed as unavailable coverage because no retained executor drives its history/state/compaction matrix. Recording its hash does not count as execution. Model quality and general conversation reliability remain unqualified.

Before any browser setup or live grant, the command waits for sequential types, protocol tests, focused domain tests, scoped lint, imports and ownership checks. Source changes during validation invalidate the result. The real-inference relay also refuses missing, failed or stale validation. The protocol rejects allowances below the minimum mandatory-case requirement before setup; runtime admission consumes the actual allowance rather than an arbitrary three-call margin. Exhaustion remains inconclusive and never starts another lot. Publication release joins the independent cleanup steps.

The mechanical report stays immutable and cannot mark the capability passed while mandatory material judgments are unresolved. `--assess DIRECTORY` prints a review template bound to the candidate, preserved source bytes, manifest and recorded before/after/published evidence. `--review FILE` adds an immutable assessment; stale evidence, changed criteria, incomplete or duplicate review sets are refused. Failed expectations, unknown charges and accounting mismatches cannot become positive verdicts through review. Exit codes distinguish acceptance, failure and inconclusive qualification (0/1/2).
