## Mechanical findings and corrections

**Malformed tool arguments.** A retained real Nemo tool response was deliberately corrupted once during delivery by replacing the framing arguments with `{`; the valid upstream reply remains preserved. Before correction, the native integration treated the SDK argument error as a generation failure: no canonical operation request, no published response, mission blocked with `invalid_output`. This is an injected transport/tool fault exposing a harness weakness, not evidence that Nemo naturally emitted malformed JSON.

The existing native generation boundary now passes unambiguously retained original argument strings through canonical operation validation. Invalid JSON becomes an explicit refused operation, allowing Pi's normal continuation and factual failed-edit receipt. The integration never executes SDK-repaired arguments. Missing or ambiguous originals still block, incomplete terminal output retains its guard, and definitions without native conversation keep their strict acceptance policy. This change is localized in `convex/integrations/piMission.ts` and uses the existing definition and operation contracts.

**Control-only framing writes.** The first repaired browser scenario passed its status assertion, but the subsequent revision audit found that `Start research now` admitted an `adjust_framing` operation. Content was identical, yet revision 4 became revision 5. The original browser assertion had not checked revision preservation; its green result did not cover this side effect. The extra write could create artificial optimistic conflicts.

Workbench tool projection now removes framing writes when all admitted messages match the existing explicit research-control grammar. The existing server framing-authority owner independently refuses a control message as the cause of a write, including a forced call. A separately admitted edit still has its own authority in a mixed response. The rule reuses `explicitResearchCommand`; no additional intent classifier, command grammar, state owner or forwarding layer was added. The owning modules are `convex/domain/workbench.ts` and `convex/domain/framingEditAuthority.ts`. The serializer profile artifact was regenerated through its existing owner because the offered tool combinations changed.
