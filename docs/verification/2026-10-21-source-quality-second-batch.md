DeepSeek V4.1 Flash remains the provisional qualification candidate for the prototype. It produced 31 accepted qualifications out of 32, against 28 for Flash 1017, and materialized contributions for 27 of the 28 substantive documents, against 24. ## Scope and results

The real production input preparers, SDK adapters, schemas, reference resolution and materializers run locally. Qualification and comparison are separate controlled tasks. Acceptance means the existing production validator and materializer accepted the result. It does not mean every contribution received independent semantic verification. The reference is investigator-authored. All required-role, forbidden-role and minimum-contribution machine checks passed on accepted qualifications. Remaining strict reference disagreements concern document-purpose classification: four accepted cases for base Flash and three for 1017, including product versus integration documentation and a documentation index classified as product documentation.

The 1017 condition has a slightly lower total bill. Base Flash has a slightly lower observed qualification cost per accepted result because it produces three more accepted qualifications. These small differences include workload and cache effects and are not a general price or latency guarantee. No perfect-score threshold is used to reject either model.

## Verified rejection causes

Saved provider responses were replayed offline through the unchanged production schemas and materializers. No response was truncated, no schema was relaxed and no additional inference was used for diagnosis.

- Base Flash's Adobe annual qualification returns 16 contributions, exceeding the 15-finding envelope, and fails materialization.
- Four 1017 qualifications fail with `period_basis_missing`: Adobe annual, Adobe quarterly, Snowflake annual and CrowdStrike annual. A declared period is missing the required supporting passage basis. These are grounding failures under the current contract, not merely long explanatory text.
- Thirteen base Flash comparisons and ten 1017 comparisons exceed the 600-character explanation bound. The Adobe forecast explanation from 1017 is 603 characters. An explanation can therefore have an otherwise appropriate verdict and still be rejected in full.
- One additional 1017 comparison has an empty explanation, below the one-character minimum.

All 96 requests received HTTP 200 responses. All 29 failed task results are validation failures. There were no transport failures, automatic retries, provider fallbacks or unknown-charge reservations.

## Semantic decisions and retrieval limits

As a separate diagnostic, the raw comparison dispositions match the grouped reference in 16/16 cases for base Flash and 15/16 for 1017. This does not convert the rejected results into valid outputs. The 1017 disagreement is NVIDIA capability: it declares no conflict despite its own explanation acknowledging named integration elements that the supplied primary passages do not establish.

The grouped reference expects 14 inconclusive outcomes, two scoped no-conflict outcomes and no conflict outcome. An always-inconclusive response would therefore match 14/16. This makes the raw agreement rate a weak standalone ranking metric. It is not evidence of universal robustness or perfect reasoning.

The Adobe numeric case exposes a concrete retrieval difference. The first batch supplies an investigator-selected annual-report table with revenue of USD 23,769 million. The grouped production preparer supplies six primary passages that do not contain that table value. The grouped reference accordingly expects inconclusive rather than the first batch's possible conflict. A comparator cannot identify the known discrepancy from evidence it never receives. More tuning of the decision model alone would not resolve this omission.

The practical conclusion is to prefer base Flash provisionally for qualification and address the comparison output contract and this retrieval gap before further model optimization or activation. The evidence does not require a more expensive model, and it does not justify dismissing every rejected comparison as a semantic reasoning failure. No repair to those production contracts was implemented in this evaluation.

## Evaluation tooling

The existing runner previously selected models only for common closed-choice cases. It now supports `--tasks qualification`, `--tasks comparison` or `--tasks qualification,comparison` together with `--models`. This is implemented in the existing CLI, not a second evaluator. Both grouped entrypoints prepare the same immutable manifest; live invocations dispatch only the selected entrypoint and phase. Native closed-choice models are explicitly rejected for grouped extraction.

The evaluation reuses one configuration function for generative routing, quoted price limits and optional reasoning/output settings. The SDK-generated live body is configured and compared with the approved exact request hash before I/O. The budget uses the actual output cap. For this batch both models use Relace, disabled reasoning, a 6,144-token completion cap and identical frozen prompts, schemas and prepared source inputs. Only model IDs, explicit provider routes and quoted price ceilings differ from the historical adapter templates. Production provider configuration remains unchanged.

The regression test first failed with `Unknown study option: --tasks`. After implementation, all 26 focused benchmark tests passed. Scoped Biome checks on the changed TypeScript files, the import checker, client typechecking and Convex typechecking passed. The global `pnpm check` stopped at the existing unrelated `noArrayIndexKey` lint error in `src/components/workbench-shell/analyzed-company-list.tsx:114`; the global format check, full suite and build were not reached. No browser gate was applicable to this evaluation-only change.

Changed existing task files are `scripts/evaluations/source-selection/study-cli.ts`, `src/__tests__/benchmarks/source-quality-study.test.ts` and `scripts/evaluations/source-selection/README.md`. Earlier runs, source captures, reference answers, product requirements, domain validators, application configuration and services were preserved. The broader implementation goal remains paused.
