## Confirmed harness findings

### Successful contextual reading does not advance Sources progress

`convex/domain/sourcesAgent.ts` credits only the plural `progressKeys` property. The shared `read_in_context` operation returns a singular `progressKey`; the existing `operationProgressKeys` owner in `convex/execution/missionData.ts` already handles both formats and is used by Workbench. Sources bypasses that normalization.

The retained CCC mission omitted two successful reading keys; Adobe omitted three. Both missions stopped at three non-progress turns. In CCC's final sequence, a refused discovery was followed by a genuinely new successful read and an empty search; the read failed to reset the non-progress counter. In Adobe, new reading and refused completion attempts similarly consumed that counter. The stop is therefore not evidence that the model only repeated identical work. It also does not prove that crediting the reads would make the model complete its task.

An independent deterministic probe imports the actual catalogue, shared fixtures and registered operations. It confirms that a successful fresh read produces a previously unseen scalar key, while the persisted Sources mission does not adopt it. No provider is called. Evidence: `progress-accounting-evidence.json` and `diagnostic-probes-final.log` under the evidence root.

Recommended correction: reuse the existing `operationProgressKeys` implementation in Sources' domain reducer. A regression must show a new passage resetting the non-progress allowance while repeated reading of the same passage does not replenish it. Keep the existing counter, deduplication and resource ceilings.

### Quotation instructions and reservation enforce different granularities

Sources' actual system instruction and documentary refusal guidance allow an exact contiguous quotation copied from a returned passage. Reservation instead compares the submitted quotation with the entire indexed passage using strict equality.

CCC submitted a 734-character exact contiguous substring of a 1,589-character returned passage. Its capture and quotation hashes verify, but reservation returned `documentary_quote_invalid`. This was not invented source text. The model recovered by resubmitting the whole passage and obtained the controlled contribution, but the initial refusal exposed an incompatible contract.

The diagnostic checks the original request against its retained reading. Two registered reservation probes confirm that the exact prefix is refused before control allowance is consumed and the full passage admits. Evidence: `quotation-contract-evidence.json` and `diagnostic-probes-final.log`. The first temporary probe failed import resolution before running; its failure is preserved separately, and the corrected explicit-alias runner passed.

Recommended correction: settle and express the accepted quotation granularity once in the existing evidence-operation contract, then align instructions and refusal feedback with it. Preserve capture binding, exact-byte verification and rejection of altered or joined quotations. Do not classify the current contiguous-substring refusal as a model hallucination or weaken evidence checks merely to make the example pass.
