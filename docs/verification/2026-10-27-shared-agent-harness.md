## Implemented Boundary

The existing Convex Workflow manager now executes durable missions around temporary invocations and persisted operation requests/results. Static inspection bindings derive tool inputs from canonical domain validators; SDK tools never execute effects. Native and model requests share retained-capture authority, validation, exact-byte/hash checks and dispatch. Qualification and comparison reuse the extracted bounded transport and retain their existing routes, prompts, fallback and domain rules.

The executor automatically supplies human instructions/decisions, obligations, working notes, the preceding observable assistant reply and triggering request/results. Exact prior observable records remain paginated. Capacity overflow blocks explicitly. Stable logical identities reuse confirmed reads; unique inspected passages establish progress. Three turns without domain progress stop the mission across continuations. Dossier accounting remains canonical in the existing preparation budget, including reasoning reservations and late factual receipts. Unknown dispatched outcomes cannot be blindly retried. Cancellation fences the run before scheduling bounded cleanup independently of its volume.

There is no default live reasoning route. The local scripted model uses the real Workflow, authority, storage and operation executor, labels invocations `simulation` and creates no fictitious provider receipt. The approved-corpus precondition of the harness fixture is synthetic and explicitly labelled; the separate protected source-review gate checks actual human approval. Neither fixture establishes model judgment, new source selection or analytical quality.

## Post-Review Corrections

The following corrections address the twelve findings against implementation checkpoint `8a4f60e`. They were made in the same architecture worktree on 2026-10-27. No independent review of the corrected diff is claimed.

| Reviewed defect | Corrected behavior |
| --- | --- |
| Confirmed model output was discarded when recovering into another execution generation. | The first retained response records whether mission authority was valid when it was observed. An authorized recovery can adopt that confirmed response in the current generation while preserving the original invocation generation and provider receipt. Late, unknown or legacy responses without that evidence cannot be blindly reused. |
| A reused operation result could disappear from the next invocation context. | Context follows the preceding invocation's persisted request IDs and current call IDs, including reused requests, rather than selecting only the newest database rows. |
| Delayed cancellation could cancel a resumed mission. | Every cancellation page carries the cancelled generation. Legacy queued cleanup without a generation runs only if the original cancellation is still identifiable. |
| Inspection rules were embedded in common lifecycle handlers. | The saved-material domain now owns initialization, context, capture pins, reuse scope, progress, obligations, completion and operation execution. The shared handlers resolve one static versioned definition and retain lifecycle, accounting and authority enforcement. |
| Malformed final model output became an empty successful operation batch. | Invalid or oversized replies produce typed blocked outcomes, bounded diagnostics and failed received-call receipts. Invalid output consumes the canonical incident allowance and does not count as successful work. |
| SDK tool representations leaked into shared definitions. | Definitions expose canonical Convex validators and neutral operation metadata. The model adapter alone builds SDK schemas/tools and returns neutral call records; the single-step and no-executable-callback guards remain enforced. |
