# Resource Policy Inventory — 2026-11-10

## Result and evidence boundary

The project has an existing resource-limits module, but effective policy is distributed across domain constants, environment resolvers, schemas, SDK settings, provider receipts, qualification relays, browser-service configuration and tooling. Moving their numbers into one file would not, by itself, correct premature termination. The first correction must distinguish actual authority and capacity from conservative proxies and caller-local cutoffs, then preserve those distinctions through transport, persistence and recovery.

The source baseline is commit `2bd0808`, which adds the approved conduct rules to [AGENTS.md](../../AGENTS.md#resource-policy-and-adaptive-execution). Tracked application code was unchanged during this inventory. Four subagents inspected runtime, documentary I/O, application/admission and evaluation/tooling. Parent inspection checked consequential findings against current source and added the preview service, which the initial lane boundaries did not fully cover. This is a project-wide policy map, not proof that every literal, transitive SDK default or test assertion was inspected.

No production refactor, environment change, service operation or application/evaluation provider dispatch was performed. Delegated inspection used the coding-agent harness; its own model usage was not measured here, so this is not a claim of zero agent cost. Existing limits remain enforced. The dispositions below are recommendations for subsequent work, not changes to an existing mandate or the installed technical contract.

## Confirmed findings

### Reviewer context admission substitutes bytes for token capacity

`scripts/evaluations/workbench-browser/campaign-review.ts:707` measures `Buffer.byteLength(JSON.stringify(context))`; line 708 compares it directly with `limits.maxInputTokens`. The mandate names that quantity in tokens (`convex/qualificationCampaignPolicy.ts:449`), and startup also uses it alongside model token capacities. The byte check is a conservative proxy, not a measurement of consumed model tokens. Earlier retained evaluations demonstrate that this local admission check can stop investigation before another dispatch. They do not establish the exact token count of the rejected context.

The source-approach runner repeats the same dimensional substitution: `scripts/evaluations/source-selection/sources-approach-runner.ts:196` adds request bytes to output tokens before comparing against `profile.contextLength`. Its reservation also multiplies bytes by an input-token price. That is conservative reserved exposure, not evidence of actual overbilling. Neither location should be repaired with an invented universal bytes-per-token ratio. Separate serialized-payload safety, model context accounting and financial reservation explicitly, using the installed native capabilities where applicable.

### Generation deadlines have independent enforcement owners

Ordinary generation is configured at 60,000 ms in `convex/integrations/modelRouting.ts:86`. Documentary control has a separate 300,000 ms setting at line 87. Provider model leases already derive from timeout plus 10,000 ms grace in `convex/providerCalls.ts:157`; documentary leases also account for remaining preparation authority. Preserve this existing relationship rather than adding another independent lease knob.

The qualification relay independently uses `AbortSignal.timeout(60000)` at `scripts/evaluations/workbench-browser/relay.mjs:374`, a 131,072-byte request bound at line 153 and a 1,048,576-byte response bound at line 398. Increasing the application timeout does not change these relay checks. Their applicability must be traced by route: `prepareCampaignScenarios` passes an optional relay origin, while `convex/execution/fixtures.ts:896` rejects a relay origin for Sources lots. The relay is therefore not established as the cause of the recent Sources interruption merely because its timeout has the same value.

A documented 60-second or five-minute value is not proof that it fits a responsive reasoning workload. The report does not endorse either number as sufficient, invent a replacement, or assume model descriptors advertise request-duration limits.

### Native context management exists, but reviewer accounting needs its own integration

Application Pi Durable missions enable native compaction and bypass the legacy fixed input-byte check (`convex/integrations/piMission.ts`; `convex/execution/invokeAgentModel.ts:179`). The campaign reviewer separately disables compaction at `scripts/evaluations/workbench-browser/campaign-review.ts:661` and meters calls by wrapping `session.agent.streamFunction`.

Reuse native context management rather than building another transcript-shortening system. However, simply enabling reviewer compaction is not yet a safe implementation recommendation: prove that its model calls pass through the same reservation, journal, settlement, cancellation and unknown-outcome controls. The inventory did not establish that coverage. Hidden retries and cache-warming calls must not be introduced as a side effect.

### A scheduling slice is not a mission-completion deadline

`convex/integrations/piMission.ts:528` checks elapsed worker time before a new model request. After 80,000 ms it raises `pi_slice_complete`; the terminal handler schedules continuation rather than treating that condition as a failed mission. The retained-operation drain similarly yields after a batch of 20. These are not hard timers that terminate an in-flight generation at the stated threshold.

The writer lease is 90,000 ms (`convex/execution/piStore.ts:38`) and is renewed on a 25,000 ms clock. The lane suggestion to derive the worker slice as `lease - 10,000` is not justified by this alone: renewal means writer expiry and scheduling fairness are different concerns. Centralize their definitions and validate their relationship without inventing an algebraic dependency or an unverified platform action deadline.

### Some apparent inconsistencies are different contracts

Manual metadata inspection defaults to a 2 MiB response bound (`convex/sourceActions.ts:24,434`), while canonical acquisition uses 16 MiB. Preparation explicitly passes `MAX_APPROVED_SOURCE_BYTES` to that same pinned HTTPS transport (`convex/sourcePreparationActions.ts:443`). These are different consumers, so the inventory does not establish that all manually supplied sources above 2 MiB fail canonical acquisition. Review whether metadata inspection needs that restriction before changing it.

Likewise, a 512 KiB inline commit threshold fragments larger native commits; it is not the same as the terminal 32 MiB retained-log ceiling. Tool pages of 50 KiB with continuation cursors are not equivalent to a whole-file refusal at 64 MiB. A model context limit, an SSE wire-body cap and a diagnostic-report retention cap also require separate policy names and units.

### Genuine duplicated knowledge and bounded-cleanup behavior remain

`convex/domain/researchPlan.ts:26` derives the maximum research-plan question count from `ASSESSMENT_DIMENSION_KEYS.length + 1`. `convex/policyEvaluations.ts:73` and `convex/evidenceMatrix.ts:28` independently hardcode 11. These consumers should share the existing derived domain rule rather than gain another tunable number.

Legacy context cleanup at `scripts/evaluations/workbench-browser/qualify.ts:884` stops after 25 pages and explicitly throws `Context cancellation did not finish`. It does not silently report success. The campaign cleanup path instead continues until `done`, requiring cursor advancement. Query page size should not become a total cleanup allowance; reuse that existing continuation contract where applicable.

## Disposition definitions

- **KEEP** preserves an established authority, security, idempotency or truthful-continuation mechanism. It does not certify every associated numeric default as sufficient.
- **DERIVE** obtains effective values from the authoritative policy, native capability, remaining grant or existing domain rule, with matching units and scope.
- **REMOVE** removes a demonstrated shadow restriction or duplicate rule after executable coverage protects the intended boundary. It does not remove the controlling authority or safety requirement.
- **INVESTIGATE** means numeric adequacy, justification, applicability or a replacement relationship remains unproven. Do not convert it into a guessed new value.

KiB and MiB denote binary byte quantities. Character limits generally follow the owner's JavaScript string-length checks unless explicitly byte-counted; they are not token or grapheme counts.

## Centralization recommendation

**Fact:** `convex/resourceLimits.ts` already owns many settings, but imports generated Convex environment state and mixes values with runtime resolution. `modelRouting.ts`, execution protocol, rate limiter, domain schemas, scripts and the separately built preview service also own policy. Some duplication is genuine shared knowledge; other equal numbers belong to different responsibilities.

**Options:** Extend the existing resource-limits mechanism and keep environment resolution at existing runtime boundaries, extracting pure declarations only where cross-runtime use requires it; or create a new configuration subsystem and migrate every consumer to it. Both are technically possible. The latter adds concepts and migration surface without a demonstrated need.

**Recommendation:** Use one authored catalog for legitimate application tunables, grouped by meaning and units. Reuse existing resolvers/owners rather than add a manager or orchestration layer. Keep actual model/provider/platform capabilities, approved immutable grants and domain-derived invariants as authoritative inputs, not copied defaults. Expose resolved effective policy, including the controlling source and narrower authority. If a separate service image requires a generated/package copy, generate it from that authored source and check parity; do not maintain independent defaults by hand.

**Not required:** A single timeout for all operations, a generic limits framework, moving all business validation into one module, or turning every literal into an environment variable. Centralization must not make unsupported caps permanent.
