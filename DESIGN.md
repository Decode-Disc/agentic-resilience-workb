# Design System: Agentic Resilience Workbench

## Overview

**Creative North Star: "The Evidence Workbench"**

An understated, precise institutional-research interface on a faint neutral grid, using Geist reading text, compact Geist Mono metadata, selective glass, and one focal surface to frame current work without competing with evidence.

**Key Characteristics:**

- Near-neutral reading surfaces on a quiet, fading workspace grid with hairline row separation.
- Geist Variable prose and locally hosted Geist Mono metadata (`@fontsource-variable/geist`, local Mono OFL).
- Analytical meaning carried by both label/glyph and tint; four workspace destinations plus an in-context inventory sheet.

The [active theme](src/assets/styles/themes/evidence-workbench.css) owns token values, the [global stylesheet](src/styles.css) owns shared utilities, and shared components own reusable variants. Local design-tool exports are not runtime inputs or parallel authorities; [PRODUCT.md](PRODUCT.md) owns product behavior and [context/TECH.md](context/TECH.md) owns enforcement.

Run `pnpm design:sync` to refresh CSS-backed tokens in this frontmatter and regenerate `.impeccable/design.json`; run `pnpm design:check` to detect drift without writing. Component capture values and static samples require manual review when runtime owners change, and light/dark palettes remain explicit.

## Colors

Ordinary primary actions use **Institutional Ink** (`primary` / `primary-foreground`). **Research Violet** (`brand-purple`) marks focus, selection, the `//` motif, and running work (`WorkbenchUiRoot` uses the reference-specific accent values from the active theme stylesheet; installed screens keep the theme's oklab `accent` mix). **Quiet Sage** (`brand-green`) marks technical readiness/recognition, while **Approval Teal** (`approved`) is reserved exclusively for positive analyst approval—never technical success, source availability, or proposed inclusion.

Source-preparation segmented progress bars use Research Violet for completed work, a contrasting neutral for the active segment (only the active segment animates while running; pause retains completed fill), and a quiet neutral for remaining work inside one pill track clipping square segment boundaries.

Use `foreground` and `muted-foreground` for reading; `surface-glass`, `surface-float`, and `surface-bar` for working panels, floating layers, and the top bar; `fill-quiet` for tracks/icon wells; and `divider` for row hairlines. Shared application inputs use `input-surface`, `input-border`, and `surface-shadow-input` (slightly darker than cards/popovers in both themes, with explicit focus and invalid rings). The Continuous thread composer instead uses the selected study's opaque card surface with a transparent textarea.

Evidence classes use `evidence-fact`, `evidence-inference`, `evidence-hypothesis`, and `evidence-unknown` with matching `tint-*` fills, labels, and glyphs. Counter-evidence uses rose (`counter-evidence` / `tint-counter`) only for an actual opposing relation. Source families remain neutral metadata.

`review` / `review-foreground` provide readable amber review markers; `destructive` / `destructive-text` supply readable destructive tints; links use `accent-foreground` (separate from `approved`). `OutcomeCard` scopes `--outcome-*` palette tokens in the active theme for reasoned appraisal (violet), limited synthesis (slate blue), justified insufficiency (warm taupe), non-establishment (blue gray), pending judgment (amber), no retained appraisal (desaturated amber), unfinished work (slate), and technical interruption (muted red).

**The Semantic Color Rule.** Research Violet identifies focus, selection, running work, and reasoned-appraisal outcomes; Approval Teal identifies analyst approval; amber identifies pending judgment; and evidence colors identify analytical meaning. Always retain the label and non-color cue.

## Typography

Geist Variable is the shared heading and body family; Geist Mono 400/500 is hosted locally with its OFL license. Consumer-specific landing headlines and composer sizing remain local.

- **Display:** responsive page titles, semibold and tightly tracked.
- **Title:** compact section titles.
- **Headline:** screen headline at 40px/44px and medium weight, reduced on narrow screens.
- **Heading:** section heading at 20px and semibold weight.
- **Reading:** the sentence under examination, at 20px and medium weight.
- **Body:** default reading text; body-sm supports compact descriptions (`AppraisalBlock` keeps local 19px/28px sizing).
- **Brief:** long reading text at 15.5px/26px.
- **Figure:** real summary counts, followed by a readable noun.
- **Label:** short uppercase monospaced metadata.
- **Chip:** uppercase monospaced section or integrity disclosure.
- **Meta:** sentence-case monospaced provenance and identifiers.

**The Shared Type Rule.** Use sentence case for controls and prose; reserve uppercase metadata and monospacing for short structural labels, counts, and provenance.

## Layout

### Shell, Start & Workspace Navigation

`WorkbenchShell` owns outer gutters (1rem, 1.5rem, 3rem across Tailwind breakpoints inside a 100rem max container) and bounded viewport mode (`data-workbench-layout="viewport"`). `StartResearchPage` owns the Start layout: compact `//` title, 610px composer column (`ResearchComposerView` owns only input presentation), Evidence layers card, company search, HTTPS references, and in-place confirmation. Dossier headers show ticker/exchange above company favicon and name.

The workspace top bar is 60px high, separating product navigation, active dossier context, and Account actions. Its right-hand `ThemeToggle` calls `useTheme` directly and persists appearance without navigation. The searchable dossier switcher (`SmoothDropdown`) replaces horizontal tabs and shows distinct scopes for repeated companies alongside `All dossiers` and `New dossier`, with a shared `DossierStatusBadge` showing live execution state even when closed.

Under the top bar sits a floating glass dock for the four sections—Overview (bubble), Sources (`Library`), Investigation (`Microscope`), and Synthesis (`Note`)—followed by a separator and workspace actions. The active section takes the violet tint; unavailable sections stay muted with a lock and explain themselves on hover/focus without inventing missing capabilities. Up to 48rem, the dock spans one row and keeps only the active section's label.

### Overview, Sources & Inventory

Overview is the dossier home: the conversation sits beside the stage panel (narrow viewports stack or toggle cleanly without a separate Progress page). The stage panel opens with the framed scope clamped to two lines, question count, a `Read framing` dialog trigger, and a compact four-stage stepper (scrolling horizontally to center the active stage on narrow panels). After the Sources handoff, the stage panel shows the preparation result matrix in place of collection lanes: documentary needs in rows vs. framed questions in columns (filled violet mark = prepared, review ring = completed search with nothing usable, dashed ring = unfinished; never labels a question as covered), with an explicit `Open sources` action, one stop/handoff statement, a quiet `Prepared by` byline, a `Show full need` toggle for two-line clamped needs, and a collapsed `History` disclosure below. Thin divider-toned scrollbars apply globally.

Sources is the document library: a matrix (subtle tint bands distinguishing Reading vs. Contribution columns without heavy rules) above a single-viewport notebook reader. The reader pairs a filterable source list (`Retained` / `Not retained`, plus `Go to conflict`) beside an independently scrolling document under a two-row header (title + external `Original` link, classification/capture meta, citation stepper, notes toggle, `Full text`, `Follow up` menu, question chips, and `Conflicts` filter). The reader opens on the first citation, folds uncited paragraph runs (`paragraphs not cited` / `Full text`), numbers cited passages, and places notes in the right margin at `>= 1280px` (or inline under each passage below `1280px`). Capture labels distinguish `complete capture` from `partial capture`; uncaptured candidates stay open leads rather than `excluded`.

`Inventory` opens from the last dock control on every section (an ink pill with icon, label, and real count pill; label drops on narrow screens). Its `InventorySheet` contains the evidence matrix and restores focus and context on close; existing dimensions are not relabelled as question-specific uses. Connected Investigation, grouped appraisal review, Synthesis briefs, and mechanism diagrams remain visibly absent/disabled until their domain artifacts exist.

### Continuous Thread & Dossier Context

START framing and post-launch dossier chat share the **Continuous thread** composition (`--chat-lane-width`, 12px gutter on phones, 48px from 640px). One canonical transcript orders analyst bubbles (right-aligned primary/card mix), unlabelled assistant Markdown replies (accessible agent identity via `AgentIdentity`, never the `//` motif), and compact expandable activity groups (latest ongoing operation visible when closed; virtualized chronological reader when open that end-follows only while at the end; terminal work folds automatically). The conversation canvas stays opaque and untextured.

A dismissible floating context card opens from the top-right header (inline right side column when the reading lane keeps minimum width, otherwise a header-anchored nonmodal popover; defaults open only on desktop framing, closed on mobile and post-launch, and preserves user open/closed preference). It holds only what the transcript does not repeat: active scope with `Change scope` / `View framing`, program question count and labels (proposed vs. accepted), retained Outputs, expandable bounded Sources summary, and a single line for running/interrupted work. Initial and retained messages share a hover/focus/touch footer with recorded creation time and Markdown copy confirmation.

Pending clarification and proposed framing occupy a foldable panel visually attached above the composer outside the transcript scroll area (clarification opens when required with one shared `Continue` action; typing deselects choices). A prepared program opens compactly (`Hide questions`/`Show questions`, numbered question rows with one open at a time, inline `Edit question` in the open row, or composer-based `Add question` / scope edit preserving ordinary drafts) and keeps guarded `Start research` outside its scroll body. On desktop post-launch, Conversation and Overview/Progress sit in resizable split panels; narrow screens default to the stage view with a fixed bottom-right `Ask AI` sheet trigger.

## Elevation & Depth

The workbench shell keeps its fixed gradient, 38px hairline grid fading downward, and 25% fabric texture (Continuous thread opts out to an opaque untextured canvas; Progress may add one subtle radial violet glow). Question-led glass panels use 68% card, 24px blur, and `shadow-glass`; `LiquidGlassCard` keeps 46% card (`glass-card`). Floating layers use 82% card and `shadow-float`; the top bar uses 55% card and 16px blur; opaque objects use `shadow-raised`. `shadow-focal` identifies one active surface (keeping reference violet drop in scoped library mode and black drop shadows on installed dark screens); `shadow-review` highlights a pending human decision.

**The Surface Hierarchy Rule.** Keep reading regions opaque inside selective glass panels, separate rows with hairlines, and reserve dashed outer edges (`OutcomeCard`) and dashed glyphs for unfinished execution or explicit uncertainty (`AppraisalBlock` decisive unknown).

## Shapes

Metadata badges use 4px corners without hover chrome (claim/counter-evidence badges add a 1px inset contour; neutral badges stay borderless; dashed variants remain outlined). Section chips use 5px corners; standard controls/inputs/segments use `radius-control` / `radius-tile`; floating layers use `radius-popup` (6px inset, `radius-option` rows); tooltips use `radius-tooltip`; Dialogs use `radius-2xl`; Alert, Accordion, Card, and `OutcomeCard` use `radius-xl`; `GlassPanel` uses `radius-2xl`; `AppraisalBlock` and `InventorySheet` use `radius-3xl`; round/launch actions use `radius-full`; source cards keep `radius-source-card`.

## Do's and Don'ts

### Do:

- Do keep tokens and variants in their runtime owners and regenerate derived documentation.
