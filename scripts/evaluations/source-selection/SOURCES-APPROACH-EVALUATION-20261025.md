# Fixed pipeline versus Sources agent: live evaluation

Evaluated on 2026-10-25. Recommendation: retain fixed orchestration as the implementation baseline for now. The agent sometimes repairs a proposal and finishes faster, but this implementation does not prepare material reliably enough to replace the fixed sequence. Neither orchestration nor enabling reasoning guarantees correct qualification or comparison. This is a recommendation from a bounded experiment, not a production routing change.

The [subsequent semantic adjudication](#semantic-adjudication-of-analyst-usefulness) qualifies that recommendation: the fixed path is an operational baseline, not an established quality winner. The review below judges relevance, support and material omissions directly, rather than treating registered qualifications as useful conclusions.

The [implemented assertion candidate and live recheck](#assertion-candidate-implementation-and-live-recheck) improve several contributions but retain material semantic failures. The candidate is available for evaluation; the application continues to default to qualification version 4.

The [2026-10-26 live inspection comparison](#live-inspection-comparison-and-semantic-adjudication) records a repeated useful agent correction, a CrowdStrike regression and two remaining harness limitations, with all 126 receipts reconciled.

## Experiment and results

The completed matrix contains 24 live trials: three companies, two approaches, reasoning disabled or medium, and two repetitions with reversed condition order. Four ServiceNow captures and five each for Adobe and Snowflake give 28 source opportunities per condition. Both approaches use the same prepared passages, experimental qualification contract, domain materializers, comparison rules and deterministic selection policy. The agent makes its own proposals through tools; its tools perform no nested inference. The [runner documentation](README.md#fixed-pipeline-versus-agent-on-frozen-sources-dossiers) describes execution and resource limits.

Registration measures whether a proposal passed the contract and was retained. An accepted qualification can contain no positive findings, and accepted findings can be wrong. These counts are not semantic accuracy scores. One fixed/medium ServiceNow trial stopped on an upstream HTTP 429, leaving its four source opportunities without qualifications; one other fixed/medium qualification exhausted its output budget. Fixed/disabled lost one qualification to duplicate contribution passages.

Six of the twelve agent trials hit the request-size limit, two ended without completing their tool sequence, and two reached the call ceiling after repeatedly submitting overlong completion notes. The agent actually executed its `complete` tool in the second Adobe/medium and Snowflake/medium repetitions. The final state retains earlier accepted work in failed missions: for example, the first Snowflake/disabled agent retained two filings before reaching the request-size limit.

All 24 mission outcomes are `partial`. The bench requires every source to be qualified and every required comparison to have complete input coverage; bounded comparison inputs remain partial even after all submitted findings are assessed. This status does not mean that every qualification failed, and documentary coverage gaps are not themselves its completion criterion.

## What the documentary review establishes

**The original negative verdict is removed structurally, but semantic contradictions remain.** The shared experimental schema excludes `no_substantive_content` and requires passage references for current/historical periods. Its absence is therefore a contract property, not a measured improvement rate against an old-schema control. In `servicenow.fixed.off.1`, website terms `p2`/`p3` are nevertheless classified as operative commercial terms even though those passages explicitly exclude the paid products. The same run labels 2024 guidance as current in October 2026. Exact references establish provenance, not that a selected label follows from the cited text.

**Passage boundaries can mix incompatible content.** ServiceNow presentation `p6` combines realized FY2023 figures and 2024 guidance. Snowflake interim `p1590` combines realized gross margins and expectations about future fluctuations. `snowflake.fixed.on.1` correctly uses `mixed_or_uncertain`; the second fixed/medium repetition and the successful Snowflake/medium agent label that mixed passage a reported outcome. The two fixed qualification requests have identical hashes. Reasoning improves some judgments without making them stable.

**Some wrong labels reach eligible coverage.** Both Snowflake fixed/disabled repetitions classify the documentation landing page as product documentation and grant product/integration coverage. Some supporting passages are only link labels such as “Snowflake Native App Framework” and “Snowpark API.” The page has useful introductions and dated preview announcements, but the linked manuals were not inspected. The reasoning-enabled results are more cautious about coverage, although they differ on whether to retain any landing-page contributions. Preserving a source, retaining a limited contribution and granting a documentary role remain separate decisions.

**Comparisons can contradict their own explanations.** Adobe thesis comparisons sometimes return `no_conflict_observed` while acknowledging that pricing, conversion or competitor claims are unaddressed, or while citing narrower Firefly indemnification provisions than the thesis claims. Snowflake `fixed.off.2` similarly uses broad partner disclosures to return no-conflict on an argument about capturing the learning loop, despite acknowledging that this central issue is not addressed. The [comparison instruction](../../../convex/domain/sourceComparison.ts) explicitly requires an inconclusive result when a material premise remains unresolved. Listing all five comparison dimensions does not establish that they were actually aligned. ServiceNow and Adobe fixed/medium results also contain accepted explanations whose literal value is `placeholder`; that word was absent from their requests.

**The agent has genuine positive cases.** In ServiceNow/disabled repetition two it repairs a rejected duplicate-passage qualification. In Adobe/medium repetition two it revises an initially empty terms qualification and retains useful contractual content. Its successful Snowflake/medium trial gives substantive, inconclusive comparisons for the article's architectural arguments and finishes its tool sequence in approximately 66 seconds. Fixed/medium Snowflake trials took approximately 175 and 200 seconds. These outputs differ in retained content and correctness, so those timings do not establish equal-quality speed superiority. The successful agent still mishandles the mixed margin passage.

**Useful evidence is absent from the shared inputs.** The frozen Adobe inputs omit captured annual revenue, quarterly revenue and RPO figures needed to examine the secondary thesis. Snowflake inputs similarly omit selected captured product-revenue and RPO values, while retaining some other metrics such as the interim retention rate. Neither approach has a tool to retrieve the omitted passages. Some comparisons also miss available equivalents, such as Adobe's later DOJ/FTC settlement chronology when checking an older index teaser. A complete capture and a useful prepared input are different things.

## Causal limits and next decision

The bench's agent interface is an important confound. Before reading any source, one ServiceNow request contains 118,677 bytes of tool definitions in a 122,016-byte request, with 66,740 input tokens reported. Repeating passage enums throughout the qualification schema creates most of this overhead. Reading several documents before qualifying them then exhausts the shared 512 KiB request boundary. Successful second repetitions instead alternate reading and qualification, allowing prior readings to be compacted. These observations establish a limitation of this implementation and route; they do not establish that a smaller agent interface would perform the same way.

The bench calls `prepareQualificationInput` without native retrieval metadata or a capture selection policy. The application can supply both through its existing source-preparation actions. The missing passages measured here therefore concern these bench inputs, not a verified failure of the currently running native retrieval path. Research-angle fields are empty; live discovery, acquisition, question-specific investigation and the full question-led conception were not evaluated. Snowflake was separately launched after development, but its captures were previously exposed and are not an unseen holdout. The documentary review is investigator-authored, including a delegated Adobe corpus review performed before reading its live outputs, not independent analyst acceptance.

The fixed path remains the more reliable baseline in this experiment, while medium reasoning is not justified as a global cure. Fixed/medium median observed duration was about 202 seconds versus 35 seconds without reasoning, with useful corrections, omitted content and invalid or unsupported outputs in both modes. Agent timings include early failures and must not be ranked as successful preparation speed. The registry provides inspectable decisions and bounded state transitions to both approaches; it does not establish semantic truth.

The next useful slice is to reuse the application's existing retrieval inputs in the bench and make comparisons operate on inspectable individual assertions, with explicit handling of mixed passages and unresolved material premises. Before another agent comparison, reduce the measured tool-schema overhead and preserve the current negative results as the baseline. This report does not authorize or claim those changes, another paid experiment, a provider switch or deployment. Increasing token allowances alone is not supported as the solution.

## Semantic adjudication of analyst usefulness

Added on 2026-10-25 after the user requested a direct judgment of correctness and relevance. The investigating assistant personally reviewed the retained final qualifications across all 24 missions, the secondary-thesis comparisons, and the decisive source passages. This is a retrospective, non-blinded judgment against the product's preparation purpose, not an independent analyst ground truth or an exhaustive truth audit of every assertion in the documents. No additional provider calls were made. Earlier results and the original archive remain intact.

The question is whether the prepared material helps an analyst examine control of context, workflows, execution and value capture as agents change software. A document deserves attention for a concrete contribution to that inquiry, not merely for mentioning the company. Preparation can be useful with unresolved questions and imperfect sources; the material failures below are misleading scope, unsupported favorable comparisons and omission of readily available evidence central to that inquiry. They are not a demand that Sources complete the downstream assessment.

### Pertinence failures hidden by the registration counts

Five missions register a Snowflake Terms qualification: all four fixed missions and `snowflake.agent.on.2`. None retains `p35`, although that passage explicitly preserves the customer's rights in Customer Data and bounds Snowflake's processing permission. Their selected clauses cover service access, fees, termination, liability or definitions; they do not replace that data-rights clause. For this product's context-ownership and data-defensibility inquiry, I would prioritize `p35`. This is a relevance judgment about useful preparation, not a claim that every contract clause must be extracted or that legal ownership proves economic control.

Five missions likewise register Adobe Terms qualifications. Only `adobe.fixed.off.2` retains `p65`; none retains `p72`. The selected privacy, screening and license clauses are not equivalent to the distinction between generative training, the Stock exception and opt-out-based content analytics. These distinctions matter when investigating data defensibility and learning loops. All were already present in the shared prepared input, so retrieval omissions do not explain this selection failure.

In the Adobe annual qualifications, both fixed/off repetitions retain `p163`/`p209`, while both fixed/on repetitions and the successful agent/on repetition omit them from their qualified contributions. `adobe.fixed.on.2` and `adobe.agent.on.2` instead retain `p299`, a workforce discussion containing headcount and attrition. Those figures can be correct and still be less useful for the inquiry than the specific Firefly conditions. Some comparison calls still receive and cite `p209`: this is a loss from the qualified contribution list, not proof that the passage vanished from every downstream input.

The same distinction matters for Snowflake. The successful agent/on mission retains general architecture and growth-risk material but omits annual `p419`, `p423`, `p433` and `p884` from its qualifications. Its interim `p1406` still preserves consumption mechanics, so saying it lost all economic evidence would be wrong. It nevertheless provides less of the directly relevant adverse material than several fixed runs and the incomplete first agent/off run. The first fixed/on repetition is similarly sparse. Fewer outputs are not automatically more discerning.

### Useful preparation I would hand to the analyst

**ServiceNow:** the captured material supports a historical description of a widely deployed workflow platform and specific restrictions within the developer/Store ecosystem. The primer's claim that this yields current AI orchestration control and premium revenue remains an attributed thesis. The 2023 presentation cannot establish 2026 monetization. The website terms cannot stand in for paid-product agreements. The useful remaining documentary need is recent primary evidence on AI adoption/revenue, product interoperability and applicable commercial scope, not another general company overview. The primer's FY2023 subscription-revenue figure of USD 8.71bn also differs from the presentation's USD 8.680bn and deserves an explicit discrepancy check.

**Adobe:** the issuer describes licensed/public-domain Firefly training data, particular indemnification eligibility and tiered plans. These support investigating commercial safety as a possible enterprise adoption advantage. They do not establish exclusivity against competitors, actual premium conversion or durable pricing power. The captured terms distinguish generative training from other content analytics. The thesis's FY2025 revenue range needs correction against the annual capture; its useful questions about AI monetization and workflow distribution can remain. Primary financial, commercial and competitive premises should be treated separately rather than granting one favorable disposition to the entire thesis.

**Snowflake:** the issuer describes a governed data/compute platform with customer-controlled external storage options. It also discloses reduced lock-in, reliance on competing clouds and the possibility that efficiency improvements reduce billable consumption unless new workloads offset them. The terms preserve customer rights in Customer Data. Together these are useful evidence for examining switching costs, platform dependency and pricing resilience; they do not prove Snowflake lacks a moat. The independent article supplies the unresolved question of who controls business context and captures the learning loop. The documentation index cannot answer it. More precise evidence about actual product permissions, business-process modeling and use of customer context would be relevant; another broad platform description would add little.

### Decision from the semantic review

There is no consistent semantic winner across these three dossiers. Fixed/off generally retains more useful specific material, but sometimes promotes weak evidence or incompletely checked arguments. Fixed/on corrects some scope and mixed-passage errors, but also produces placeholders and loses important available contributions. Agent/on produces some good cautious comparisons, particularly in Snowflake, yet repeats Adobe's unsupported favorable comparisons and omits pertinent material. Agent/off occasionally retains useful material or repairs a rejected proposal, but does not establish an overall analytical advantage. Missions with no registered proposals provide no semantic result to grade; they remain execution failures, not incorrect analytical conclusions.

My recommendation is to keep the fixed path only as the working execution baseline and not adopt the agent or globally enable reasoning on the strength of this experiment. That is not approval of the fixed path's semantic quality. The immediate quality target is visible in the retained material: prioritize contributions that change the architectural inquiry; separate the exact supported proposition from the rest of a mixed passage; and keep unresolved material premises out of favorable comparison dispositions. The corrected judgments above supply concrete examples for that work. No additional paid batch is needed to decide that the present counts do not justify an architecture switch.

The evidence remains bounded to the frozen bench inputs. There was no new live discovery, independent verification of the companies' statements, final investment conclusion, unseen holdout or production acceptance. No application code, provider routing or deployment was changed by this adjudication.

## Assertion candidate implementation and live recheck

Implemented and evaluated on 2026-10-25 after authorization to correct the passage–contribution–comparison path. **The candidate does not yet pass the intended analytical checks and is not the application default.** It retains useful data-rights contributions and makes several formerly favorable comparisons inconclusive. It still misses Adobe's financial discrepancy, overstates Snowflake index coverage and labels some incompletely examined premises as aligned. This is a failed quality gate with concrete improvements, not a completed reliability claim.

### Implemented boundary

Qualification version 5 requires a precise assertion in the existing `summary` field, its relevance and its applicability scope, while retaining immutable quoted passages. Distinct assertions can share a mixed passage. Missing contribution basis is rejected by the materializer and persistence owner. Versions 3 and 4 retain their executable contracts and historical request identities.

For version 5, comparison receives the stated assertion and scope. It records one to four material-premise assessments with exact primary references; code derives the overall disposition and validates it again at persistence and reuse. A possible conflict remains visible; otherwise an unresolved premise makes the contribution inconclusive. Author-reported factual premises in secondary-analysis roles also require comparison. Retrieval queries use the explicit assertion rather than unrelated surrounding text. These controls enforce structural consistency; they cannot establish that a model correctly identified and assessed every premise.

The standalone bench explicitly selects this candidate. It reuses structured extraction and the full-document-first qualification policy, and comparison can search the complete structured capture rather than only previously selected qualification excerpts. It still does not replay Convex native search. New `--approach` and `--reasoning` filters allow a fixed/off recheck without another architecture matrix. Domain owners, provider routes, cumulative limits and the approval workflow remain shared; no dependency, second workflow engine or UI was added.

After the quality failure, the application default was kept at version 4. The version-5 candidate remains explicitly executable in the bench, and any recorded version retains its own resumption contract. An executable audit confirms the current candidate reproduces all 19 qualification request hashes from the live study after that default-selection change. The observed candidate code is retained separately from the final code with its application-default guard.

### What caused the execution limitations

**The large tool-definition problem was reduced, but cumulative reading authority is still coupled to a request-size limit.** The six agents encounter ten `inspection_context_limit` rejections, all in CrowdStrike. `readPassages` merges inspected passages and their neighbors into the same 128 KiB qualification request. After enough additions, even a request for one already-inspected passage can fail because its context expansion would grow that accumulated request.

This mechanism was reproduced without any model call through the actual frozen registry. In CrowdStrike repetition two, the existing source context reaches 126,608 and then 130,190 bytes. The agent reduces its rejected request from several keys to `p89` alone, yet it still fails. Restoring a fresh baseline and reading the same `p89` succeeds and returns three passages. The problem is therefore not that this passage is unavailable, nor a provider context-window error. It is the harness's coupling of retained evidence to a single cumulative request. `analysis/context-limit-replay.json` preserves the replay and shows that all the rejected requested keys were already inspected. Splitting the batch cannot repair this condition.

**Whole-document serialized proposals create a second burden.** Ten qualification submissions are rejected: seven events for overlong summaries, one for more than two contributions in a role, and two for invalid inner JSON. One further proposal uses a stale qualification context. The two invalid JSON strings are identical 8,085-character proposals missing closing syntax. Their parse failures are converted to `null` before canonical validation, so the returned diagnostic says an object was expected rather than exposing the actual syntax location. This feedback is insufficiently specific for recovery.

The agent sends an entire qualification as a JSON string, while the fixed audit uses structured output. Canonical post-validation preserves evidence integrity, but does not give the provider the same structural constraint on the string's contents. These failures therefore do not isolate planning ability or documentary judgment. A narrower structured correction operation could preserve untouched findings and avoid asking the model to reserialize a full dossier object to correct one contribution. It must still apply the full canonical validation and revision checks.

**The fixed audit is operationally successful but analytically passive.** Its thirty reasons explain why the selected contributions appear coherent, including the Adobe article, without requesting any cross-source search. That is an observed failure to surface an omitted premise, not evidence that the premise was absent from the input. Showing the existing qualification may encourage anchoring, but this experiment does not isolate that cause. A source-first premise inventory before comparison with the provisional qualification remains a testable follow-up, not an established fix.

The agents use their budget rereading and rewriting existing material. None reaches `search_captures`, `prepare_comparison` or `submit_comparison`. The experiment consequently provides no live quality result for an agent-initiated search and no new comparison-quality result. It would be wrong to conclude either that the native search failed or that the remaining semantic errors prove an intrinsic limit of all agents. This evidence applies to this DeepSeek route with reasoning disabled, this task and this harness.
