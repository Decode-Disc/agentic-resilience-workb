# Technical Contract

## Authority and Boundaries

This document owns the current architecture, persistence, workflow, provenance, provider and security contracts. [PRODUCT.md](../PRODUCT.md) owns analyst behavior and acceptance, [AGENTS.md](../AGENTS.md) owns working and verification instructions, and the [roadmap](../docs/ROADMAP.md) separates delivery, dated verification and activation. Contracts for unfinished stages remain requirements, not claims of implementation. Historical ADRs preserve rationale without adding obligations outside these references. Discover actual implementation locations through repository exploration rather than maintaining code or test links here.

TanStack Start owns the web/SSR layer, with strict TypeScript, React and shadcn. Convex owns domain policy, structured persistence, reactive updates, artifacts, audit events and quotas. Convex Workflow is the single durable orchestration engine, including human waits, retries, cancellation and recovery. Vercel AI SDK supports typed provider adapters. Native Convex search owns derived retrieval; optional hosted embeddings do not introduce another state owner.

Keep domain records, persistence, orchestration, acquisition/normalization, model routing, analytical policy and UI projections distinct. UI components and SSR functions do not own evidence policy. Provider-specific SDK types and model identifiers stay behind adapters and configuration. CIK is canonical company identity; ticker, legal name, exchange and provider metadata are mutable. Retry, association and deduplication identity cannot depend on mutable labels unless a deterministic fixture explicitly owns them.

No second workflow engine, PostgreSQL, separate object store or custom realtime transport is part of the baseline. Eve and Vercel Workflow remain alternatives requiring demonstrated need and an explicit decision. Vercel Hobby is an acceptable hosting option only when its verified limits support the prototype; the technical baseline does not promise a free deployment. Model routes, access credentials, resource configuration, showcase identity and deployment URLs remain configuration data.

Local development gives each Git worktree its own native Convex deployment and state. Native configuration and instance identity remain authoritative; an ignored runtime manifest projects verified backend, site, web and preview origins and owned processes without secrets. A repository-wide startup lock serializes native backend allocation across worktrees, then releases after identity verification. Web and preview listeners publish their actual available ports. Application development commands and protected browser tests resolve those origins rather than assuming shared fixed ports; cleanup affects only processes owned by the invocation.

## AI Use and Deterministic Execution

Model assistance is permitted at explicitly defined points in any product phase, including framing or query planning before source acquisition. Source availability is not a blanket condition for an AI call. Justify each model-backed task or mission by its purpose, expected result and need for semantic interpretation or reasoning. Where existing rules and data resolve the work reliably, keep it deterministic; do not introduce a generative intermediary for a lookup, validation, count, state transition or formatting operation that code already handles.

Define the calling task or mission, its allowed inputs and output use, and its execution conditions before activation. Dispatch remains subject to the [provider boundaries](#provider-boundaries) and [cumulative resource accounting](#context-recovery-and-resource-accounting), including reasoning and control calls. The system authorizes work through code; it does not call another model merely to decide whether a routine operation needs AI. This policy preserves adaptive mission reasoning and mandatory targeted submission controls without requiring another model for every action.

Framing proposals and research hypotheses prepared before acquisition do not establish company facts. Documentary and analytical assertions still require their admissible evidence and controls. Permission to use models across phases does not start Sources or Investigation before Start research, bypass an analyst prerequisite, or activate a provider. Existing runtime restrictions remain under the [implementation transition](#implementation-transition) until their replacement is implemented and verified.

## Agentic Missions and Shared Operations

Three specialized mission agents work within system-owned execution: Sources conducts documentary inquiry; Investigation contributes assertions and investigates the framed questions; Synthesis connects retained appraisals. The system fixes each mission's authority, scope, applicable versions, permitted operations, resource bounds, expected artifacts and progression conditions. The agent chooses useful readings, confrontations and proposals from mission start; it is not activated only after a predicted risk. One shared mission and continuation protocol runs on Convex Workflow. Business workflows retain their phase transitions; no second orchestration engine or general capability framework is selected.

Authorized native calls and agent tools reach the same deep business operations. The domain implementation owns its authoritative input/result schemas, validation, policy, versions, persistence, effects, reuse conditions and known dependent work. The tool binding derives its input schema from that contract and supplies its description and execution binding. Server-owned context supplies authority; model arguments cannot grant it. Mission exposure is least-privilege, not a separate implementation or unrestricted access to the catalogue.

| Business operation | Domain responsibility | Agent exposure | Controlled result |
| --- | --- | --- | --- |
| Consult mission state | Dossier and preparation | All three | Compact scope, versions, references, progress, restrictions and pending work. |
| Search available material | Documentary material | All three | Candidate passages, reproducible references and search limitations. |
| Read in context | Documentary material | All three | Exact passages, surrounding context, observed links and applicable restrictions. |
| Make a source consultable | Sources | Sources | Acquired or reused content with its own capture and provenance. |
| Submit documentary qualification | Sources | Sources | Document contributions and restrictions with targeted diagnostics. |
| Request a targeted documentary check | Sources | Sources | A statement's documentary support, scope and limits, including before qualification. |
| Contribute to the inventory | Shared inventory | Investigation | Assertions, corrections and question-specific uses admitted under shared rules. |
| Request a documentary complement | Workflow | Investigation | Grouped decisive needs transmitted within the single permitted phase. |
| Submit appraisals | Investigation | Investigation | Controlled responses by question, proposed for grouped analyst review. |
| Request analytical re-examination | Workflow | Synthesis | A concern or necessary new premise routed to Investigation for available-material examination. |
| Submit synthesis | Synthesis | Synthesis | Jointly controlled mechanism diagram and argued note, or reasoned non-establishment. |

These are functional entries, not frozen SDK signatures or a generic all-purpose API. Consultation, explicit-query search, exact reading and handoff authorization need deterministic boundary checks, not a generative intermediary. Search and reading respect mission-specific access and permitted uses. Completion uses artifact references rather than another coordination tool.

Making a source consultable targets an authorized candidate or actually observed link with its recorded origin, and requires the destination's own retained content. A URL, index label or guide does not establish that its destination was read or qualified. Sources returns qualified documentary material; it does not directly create analytical inventory assertions.

### Shared Execution Structure

The shared executor centralizes execution guarantees while business knowledge remains with its existing owner. The following structure defines responsibilities without requiring one file per concept.

| Code boundary | Single responsibility owner |
| --- | --- |
| `convex/execution/` | Shared execution contracts, mission lifecycle, operation requests and outcomes, suspension/continuation, repetition controls and causal trace references, using the existing Workflow manager. |
| Static versioned agent definitions | Mission instructions, context construction, allowed operation references and domain-owned result/completion criteria. Concrete models remain routing configuration. |
| Existing domains and integrations | Business operations, semantic criteria, evidence and artifact models, acquisition, provider adapters, attempt receipts and cumulative accounting. Extend these owners rather than introducing a parallel retry or budget subsystem. |

Adding an agent supplies its definition to the shared executor, without another loop, retry policy or accounting implementation. Adding an operation supplies its domain contract and implementation once; native callers and generated tool bindings use the same controlled entry. Reuse existing schema derivation mechanisms rather than adding a schema language. The available definitions and operations form a static catalogue; dynamic plugins and a workflow language are outside this design. The execution core enforces required control outcomes without absorbing documentary or analytical criteria.

The initial executable definition is read-only saved-material inspection, with mission-state consultation, approved-capture search and exact contextual reading. It grants no acquisition, source-selection, qualification, analytical or human-decision authority. Qualification and comparison reuse the extracted bounded invocation transport and retain their existing domain protocols. Agent reasoning has no default authorized live route; local scripted invocations are labelled simulation and create no fictitious provider receipt. Sources, Investigation and Synthesis remain subsequent integrations.

Initial inspection limits are sequential dispatch, four requests per response, at most one model step per invocation (including invalid tool calls), a fixed cumulative 15-minute dossier execution window, a 60-second model attempt, 6,144 output tokens, a 128 KiB complete context/schema envelope, 16 KiB working notes, 64 KiB operation results and history pages of at most 20 events. Three consecutive turns without new domain progress stop the mission; search counts distinct inspected passages, not result-set combinations. Required context overflow blocks explicitly. Existing dossier work/incident accounting remains the single cumulative owner, with its installed default allowances of 120/40; resumes preserve consumption, repetition state and deadline. Confirmed observable model output is retained before Workflow adoption so a recovered invocation can use it without another paid call. Unknown dispatched outcomes cannot be replayed blindly. Cancellation fences the dossier immediately and schedules bounded, traceable request/mission cleanup independently of its volume.

### Mission Lifecycle and Operation Handoffs

| Execution concept | Retained identity and state |
| --- | --- |
| Agent definition | Static identifier/version, instructions, operations and result criteria. |
| Durable mission | Stable identity, dossier, objective, authorized scope, applicable versions, obligations, result references and continuation state. |
| Temporary invocation | Mission or bounded-task reference, agent/task version, actual supplied context and provider-attempt reference. It ends when it returns control. |
| Operation request | Causing invocation or system action, operation/version, validated arguments or input references, expected domain versions, logical identity and explicit outcome or pending obligation. |

Durability belongs to the mission and retained work, not to a live JavaScript instance or hidden model reasoning. A bounded one-shot task uses the same authorized invocation and tracing boundary, retaining its results without promising conversational continuation. Definition and contract versions remain explicit on continuation; an incompatible deployment requires a defined compatibility path or an explicit stop.

Ordinary handoff suspends between operations: retain the agent's request before effects, dispatch the shared business operation, retain its confirmed result or waiting state, then authorize a fresh invocation with that result and useful context. A domain operation may be deterministic, include bounded model-assisted work, or request an authorized mission. Sources, Investigation and Synthesis cooperate through their defined business requests; there is no unrestricted agent-spawning tool. Required internal checks remain system-owned. A long wait retains its correlation and releases the invocation; its result wakes only the matching eligible continuation.

Every operation requested in one response receives an explicit outcome. Mutations execute sequentially by default, revalidating expected versions after each effect; conflicting or stale remaining requests return diagnostics rather than executing blindly. Independent reads may use explicitly bounded concurrency. SDK tool execution cannot bypass this dispatch boundary or introduce implicit concurrent mutations. Completion remains a proposal checked against domain-owned artifacts and controls under the [workflow contract](#workflow-and-revision-contract).

Handoff is distinct from dossier cancellation. Cancellation fences adoption and future work even when an already dispatched action finishes. A continuation inside an active dossier does not claim another visitor slot; a resume that makes the dossier running atomically claims the existing slot and advances its execution generation.

## Workflow and Revision Contract

```text
Company, optional angle and public references → proposed framing and mandate
→ optional refinement → explicit Start research
→ Sources: shared documentary preparation
→ Investigation: common inquiry and shared inventory contributions
→ when useful: one grouped bounded documentary complement by Sources
→ Investigation: re-examination and appraisals
→ grouped analyst review of identifiable appraisal versions
→ at least one retained appraisal → autonomous Synthesis
→ jointly controlled diagram and note, or reasoned non-establishment
```

Start research fixes the framing before Sources or question investigation starts. Source selection operates under the product mandate instead of the target requiring a routine corpus-approval stop. Authority and permitted-use records remain versioned and inspectable; removing the human stop does not remove source admission, rejection, integrity or audit. The exact mandate, exception thresholds and replacement persistence transition must be specified before activating that authority.

Initial Sources preparation cannot spend the later documentary complement merely to fill source roles. Investigation first groups decisive needs across questions; one complement phase may contain multiple bounded searches and readings. It is optional, shared and dossier-wide. Synthesis re-examination uses available material only and cannot initiate another documentary phase. Initial observed-link following stays within initial preparation authority.

A grouped review binds each human decision to the identifiable appraisals and versions included. No unreviewed proposal becomes retained by default. An empty retained set remains at review, without Synthesis or a documentary-insufficiency outcome. Material proposed changes to retained judgments require targeted human intervention; recovery and favorable later controls cannot adopt them automatically.

Completion checks current expected artifacts, references, control outcomes, versions and prerequisites, not model-turn termination or an agent's success message. Each assigned need and engaged check has an explicit outcome. Finding a passage does not finish its required examination. An unfinished check blocks its conditioned use while independent work may continue. Useful partial work, justified analytical insufficiency, pending judgment, technical incompleteness and reasoned synthesis non-establishment remain distinct; no guarantee of exhaustive omission detection is implied. Concrete lifecycle and completion schemas remain implementation work.

## Semantic Controls and Analytical Outputs

Structural checks at every domain boundary establish authority, schema, references, hashes, versions and reproducible quotations. Mandatory targeted semantic controls attach to known submissions: documentary qualification, inventory assertions and their uses, appraisals, and synthesis. They do not depend on first detecting a semantic risk. Consultation, search, reading and handoff do not each require another verifier. Sources also has the targeted documentary-check operation.

The system executes verification as bounded targeted model work under shared capability and policy, not a permanent critic agent or a second dossier-wide research pass. A result records the examined object and use, evidence versions, applicable rules, scope, conclusion and limitations. Incomplete execution differs from insufficient support. Precise field, reference, version and execution diagnostics return to the responsible mission; the verifier does not silently rewrite proposals in an internal correction loop. A plausible unexamined remainder cannot inherit a successful partial check.

| Boundary | Semantic responsibility |
| --- | --- |
| Documentary qualification/check | Passage fidelity, period, modality and attribution; coherence of contributions and restrictions; comparison of genuinely comparable statements. Distinguish supported, documentary conflict, not established and technically unfinished. No economic interpretation is established merely by qualification. |
| Inventory contribution | Evidence and permitted use; Fact/Inference/Hypothesis/Unknown classification and company/activity/temporal scope; rationale for each supporting, opposing or contextual question use. Admission precedes use, not appraisal submission. |
| Appraisal submission | Reasoning from assertions through assumptions and mechanisms to possible economic consequences; rival interpretations, objections and decisive unknowns genuinely constrain the conclusion. Every assigned question receives an appraisal or justified insufficiency after inquiry. |
| Synthesis submission | Justification of new relationships and transversal inferences; fidelity between the reference diagram and the fully reasoned note; scope, conditions, evidence and limits of an alternative non-establishment finding. |

Reuse a control only for an explicitly referenced unchanged object and use whose evidence versions, rules and current restrictions remain valid. Revalidate authority and references deterministically. A new use needs its own use examination; a modified assertion needs its own examination; resulting-artifact coherence still applies. Do not ask another model whether differently worded assertions are equivalent. Documentary support does not validate a new inference, and retained appraisals do not validate new synthesis arrows. An unrelated revision does not require all earlier controls to run again.

The company inventory is shared, with canonical assertions and separate question-specific uses; useful context need not have a forced question link. Evidence presence, including an Unknown link, does not establish an answered question. Documentary integrity, admissible analytical use and human adoption are separate authorities. Exact assertion identity, correction propagation and freshness schemas remain open; no complete incremental dependency engine is selected.

A targeted change preserves unaffected content, reconstructs the resulting artifact and executes known required dependent checks through the operation owner. It is not arbitrary JSON patching or whole-artifact rewriting by the caller. Adverse findings restrict affected uses and flag known dependents for re-examination without declaring the entire dossier false. Later positive findings preserve prior objections and explain their resolution.

Synthesis can verify existing evidence and explain new relationships, but a necessary uninstructed premise is routed through Investigation for inventory admission and appraisal effects. Investigation returns a proposed revision or a reasoned maintenance of the appraisal. Pending material human revision remains explicit. Joint limited diagram-and-note delivery is permitted only when the unaffected base supports a coherent useful scope; delivery waits when the overall interpretation depends on the contested premise. Synthesis non-establishment requires an instructed retained base, not an empty review, technical interruption or pending judgment. There is no routine final synthesis-approval checkpoint.

## Context, Recovery and Resource Accounting

Context continuity is part of the continuation contract. Compact context is a working projection of retained information. Keep evidence and completed work outside the model window; later requests must not accumulate every previous reading. Tool schemas cannot enumerate a whole corpus. Cross-dossier learning and institutional memory remain outside scope.

| Context layer | Preservation and continuation |
| --- | --- |
| Required context | Automatically supply mission/scope, applicable human instructions and decisions, constraints, current versions, active work, open needs, the request causing suspension and its returned result. Explicitly identify changed instructions or versions. |
| Mission working memory | Retain examined avenues, open hypotheses, rejected interpretations with reasons, pending checks and intended investigations. Working notes remain distinct from established facts and human decisions. |
| Retrievable history | Automatically retain usable observable invocation inputs/outputs, operation requests/results, reading references and artifact versions, directly or by reproducible reference. Earlier detail stays accessible when removed from the current window. |

Preservation cannot depend on the agent remembering to invoke a save-memory tool. Supply the awaited result and necessary continuation state directly; offer scoped retrieval of prior readings and exchanges. A summary or working note never replaces exact evidence. If required context exceeds the allowed capacity, return an explicit context-capacity block rather than silently dropping instructions or unfinished work. Reading windows, context assembly and storage shapes remain implementation choices; retaining accessible context does not establish that a model used it correctly. Secrets and hidden reasoning are excluded; rejected raw provider diagnostics retain their separately specified bounds and explicit truncation.

Preserve each operation's confirmed results and pending obligations. Bounded model work within an operation is not one atomic database transaction across external I/O. Continuation uses retained domain state and compact context rather than replaying the complete conversation. The system organizes required follow-up checks so the mission agent need not remember to schedule them.

Automatically continue a confirmed recoverable interruption only while mandate, execution authority, versions, cancellation fences and remaining bounds permit it. Reuse confirmed work; unknown provider outcomes authorize no blind repetition. One shared attempt policy authorizes model retries, with automatic SDK and Workflow model retries disabled. A business refusal, analytical uncertainty and technical incident remain distinct. Recovery cannot cross a human prerequisite or adopt a revised judgment. Persist explicit unfinished work when continuation is unavailable. The generation, lease, idempotency, telemetry and public-address safeguards below continue to apply.

Protect resources cumulatively across the dossier and count all actual provider calls, including agent reasoning, model-assisted operations and semantic controls. Tool counts do not substitute for call accounting; continuation never resets consumption. No arbitrary per-agent quota or reserved finalization share is selected. Hard time and resource ceilings may leave work incomplete. Parameters for the three target business missions remain to be set before activation; the installed limits below continue to govern existing execution.

### Loop Prevention

Reuse confirmed results for unchanged operation inputs and versions when their domain contract permits it. A fresh invocation or generation does not itself create a new logical operation. Deterministic repetition policy considers the objective, operation, parameters, examined versions and previous diagnostics across invocations. Domain owners define relevant observable progress, such as newly inspected material, a changed contribution or a resolved obligation; another identifier, event or message alone is not progress. Legitimate rereading to restore context remains possible.

Mission requests retain their cause and objective and obey the [documentary and analytical return bounds](#workflow-and-revision-contract). The initial inspection threshold above is binding; the three target missions still need their numerical re-examination and non-progress thresholds before activation. Cumulative hard bounds also constrain semantic cycles that repetition detection does not recognize. On a repetition stop, retain completed work, cause and remaining obligations; do not automatically relaunch an identical mission under unchanged conditions. Any later continuation still requires valid authority, an admissible reason and remaining shared resources.

### Traceability and Typed Outcomes

Every significant business operation, whether native or agent-requested, retains its actor, cause, inputs or references, examined versions and outcome, including rejected or blocked requests. Correlate dossier, mission, invocation, request, logical operation, provider attempts, controls and produced revisions. The logical operation identity survives continuation; execution generation and attempt number remain separate. Domain results stay with their owner and the execution record retains references. Product progress remains a projection of persisted work; deterministic actions create no fictitious provider receipt.

A previously authorized provider attempt may receive a factual terminal receipt after cancellation without adopting its business result, advancing the mission, claiming a slot or authorizing another call. Receipt closure validates that exact admitted attempt; business adoption independently checks current authority, versions and execution generation. Evolve the existing path-specific receipt behavior with focused checks rather than removing its guards globally. External exactly-once execution is not promised; confirmed results are reused and business adoption remains idempotent.

Typed execution outcomes distinguish controlled success, waiting, version conflict, missing configuration, resource/repetition stop, technical interruption and unknown provider outcome. Context-capacity blocks are explicit. Analytical insufficiency and synthesis non-establishment remain domain-controlled conclusions, not replacements for these execution states. Isolate work with an unknown effect and continue independent authorized work when possible. Analyst-facing projections translate these outcomes under the product copy rules while protected diagnostics retain the relevant boundary and cause.

Persisted and external data require runtime validation and closed lifecycle values. Preserve corpus, source, claim, link, assessment, map and brief revisions. Later additions cannot silently mutate prior results. Introduce final-model concepts only when observable behavior requires them.

A `SourceVersion` stores the canonical retrieval URL, content hash, media type, byte/page counts, retrieval/normalizer versions, metadata and normalized artifact storage identity. Changed fetched content creates another version; the same logical operation/hash reuses its result. Each `SourcePassage` belongs to one version, with exact quotation, normalized quotation hash, stable order and typed web/PDF locator. A quotation that cannot be reproduced from that version is structurally invalid.

`ClaimEvidence` alone assigns `supporting`, `counter` or `context`; discovery category, recommendation, source family and company linkage never pre-assign that relationship. `ClaimDimensionLink` binds one claim revision, dimension and extraction/corpus revision with `generated` or `analyst` origin, bounded rationale and the generating task when applicable. Every `Unknown` references an unresolved research-plan question and a context passage. Question backfills are protected, paginated and idempotent, using persisted company identity, dimension keys and bounded angle without changing the original plan or inventing provider-derived questions.

`EvidenceSourceStatus` is scoped to the frozen accepted source and execution generation, with `queued`, `running`, `succeeded`, `partial` or `failed`, bounded reasons and counts. `sourceReviewItems` is a derived source/revision projection maintained transactionally with decisions, and reconstructible through an idempotent administrative backfill. Summaries use bounded indexed reads, collection pages use native cursor pagination, and approval verifies authoritative effective decision heads rather than trusting historical accepted rows.

Workspace search parameters use `section=progress|sources|investigation|synthesis`, validated mission-specific `subsection` values and optional `inventory=1`. Historical `evidence` destinations open Inventory over Progress; `assessment`, `map` and `brief` map to Investigation/Review, Synthesis/Mechanism and Synthesis/Full brief. These are presentation destinations, not authorization or execution transitions. Missing mission capability stays unavailable regardless of a legacy lifecycle value. The inventory reuses existing authorized evidence queries and preserves matrix state after first opening. Dock opening adds a history entry; closing a dock-originated sheet returns to that entry's predecessor, while closing a direct-linked sheet removes only the inventory parameter. Source-review context survives overlay opening, refresh and browser history.

Protected source-review navigation uses validated `view` and `coverage` search parameters under `section=sources`: absent `view` means overview, `adjust` opens adjustment and `inspect` opens candidate inspection. Accept a canonical coverage-role key only during inspection. Showing all candidates removes `coverage`; returning to the overview removes both parameters. Refresh, direct links and browser history restore context without triggering discovery, decisions or approval. Standalone illustrative consumers retain local navigation through the existing component interface. Overview membership/counts and adjustment use the same bounded decision projection.

Large artifacts live in Convex File Storage. An upload lease records `reserved`, `uploaded`, `committed` or `orphaned`, attaching the storage ID as soon as available. Upload and database commit are not atomic: require one committed referenced artifact per logical operation, not zero transient uploads. Failed finalization marks an orphan and attempts deletion. Protected paginated cleanup reconciles old leases and storage after a safety interval, covering crashes before lease attachment and protecting both preparation captures and analytical versions.

## Legacy Workflow and Revision Contract

The delivered path includes the human source checkpoint and the fixture-gated evidence handoff. The later dimension review and derived outputs were planned but are not certified as delivered; they are superseded by the question-led target. The legacy lifecycle values below do not certify that every declared stage has an implemented path.

```text
Existing path (claim generation is fixture-gated):
Explicit company selection → preflight confirmation → atomic analysis reservation
→ authoritative identity revalidation → public-evidence sufficiency review when needed
→ research plan → discovery → bounded capture/qualification/comparison
→ inspect alternatives and one finite supplement → source proposal → corpus approval
→ exact approved materialization → analytical claims → structural/policy validation
→ evidence_ready (arbitrary live inputs pause before claim generation)

Formerly planned continuation (not certified as delivered; superseded):
Counter-evidence within approved corpus → dimension review → derived views
→ finalization after all ten dimension decisions
```

| State family | Values |
| --- | --- |
| Research lifecycle | `draft`, `checking_public_evidence`, `awaiting_evidence_sufficiency_review`, `discovering_sources`, `awaiting_source_review`, `corpus_approved`, `extracting_evidence`, `evidence_ready`, `assessing_dimensions`, `awaiting_assessment_review`, `completed`. |
| Execution | `idle`, `running`, `paused`, `failed`, `cancelled`, `completed`. |
| Workflow step | `queued`, `running`, `completed`, `needs_review`, `failed`, `skipped`. |
| Completion outcome | `completed_assessment` or `insufficient_public_evidence`. |

Enforce transitions server-side. Execution status is separate from analytical lifecycle; failures and cancellation cannot invent analytical stages. A pause identifies the source/assessment checkpoint or the technical `claim_generation_unavailable` condition. Persisted `RunEvent` records alone drive product progress.

Preparation is opt-in through `SOURCE_QUALIFICATION_ENABLED=true`. New workflows snapshot an optional `prepareSources` argument; absent arguments retain the historical discovery-to-review sequence. Public preparation starts reject while disabled. Legacy refresh is explicit, never a page-render side effect. Preparation may retain its own handle alongside a legacy main workflow waiting for approval, on the same workflow engine. Activation remains subject to the bounded model and protected-journey acceptance recorded in the roadmap.

An editable draft accepts several additions and decisions. Approved membership is immutable; a change creates another draft and approval checkpoint. Unchanged captures and exact-input qualifications can be reused, but this does not promise complete incremental recomputation of downstream claims or briefs. New draft proposals use the persisted run pointing at that revision, not a stale prior-revision snapshot.

Approval and analytical start are one atomic handoff: verify ownership, approved revision, expected generation and visitor capacity; freeze the latest accepted decision heads and their authoritative IDs; claim the execution slot; advance generation; start the separate analytical workflow with a revision-bound idempotency key. Sources whose accepted decisions were superseded by pending/rejected heads confer no authority. Historical `corpus_approved + idle` dossiers retain the protected start operation. A reopened legacy corpus without a waiting discovery workflow uses this same evidence-execution owner. Emit extraction progress only after start. Sources remain inspectable read-only during and after extraction.

Store an active workflow ID only while execution runs. Completion compare-and-clears its own handle, never a newer execution. Every retryable operation binds run, workflow version, generation, corpus revision, step and attempt. Any resume that can become running atomically claims the visitor's single slot and advances generation. Check ownership, operation lease, generation and cancellation before I/O and again before persistence. Stale, duplicate or cancelled work cannot advance state or trigger another paid attempt. Retries do not duplicate evidence, reservations, call records or side effects.

`evidence_ready + idle` requires terminal frozen source branches, at least one structurally valid reproducible passage, a terminal claim pipeline and at least one valid claim visible in the matrix. Individual source failures and visible `needs_review`/`blocked` policy outcomes do not by themselves prevent that handoff.

If a live dossier has passages but no claim adapter authorized for their hashes, pause at `extracting_evidence + paused + claim_generation_unavailable`, set the claim step to `needs_review`, and release execution and the visitor slot. Do not fabricate `Unknown`, success or assessment access. Owner/administrator retry first checks capability; if unavailable, change no state or generation, claim no slot and issue no call. A valid retry claims the slot, advances generation and starts a current-version workflow scheduling only incomplete claim/policy steps from persisted artifacts. Cancellation prevents retry until explicit resume reclaims the run.

## Source Preparation and Selection

These installed preparation policies, protocols and explicit recovery controls remain applicable to existing executions. Their pre-Investigation supplement is a compatibility mechanism, not the target analytical complement phase. Reuse their integrity and accounting mechanisms without carrying forward obsolete progression or human stops.

### Captures and qualification

Capture the exact normalized representation before qualification. Identity includes source, requested/resolved URLs, retrieval time, stored representation, content hash and retrieval/normalization versions. References bind exact quotations and offsets to those bytes. Pin captures and references on proposals. ### External I/O and transient preview

Authorize every protected operation and applicable lease/generation before DNS, SDK or HTTP work. Revalidate before persistence. Apply least privilege, server-only secrets, safe logging, content sanitization and bounded parsing/decompression. Treat source text and model output as untrusted evidence, never system instructions. Defend against embedded prompt instructions and outbound SSRF, including redirects and DNS rebinding.

Visual preview uses a separately packaged Playwright service, behind an authorized Convex action, never direct browser-to-service traffic. The service accepts authenticated `POST /render`, creates a fresh context without prior cookies/storage/credentials/downloads, returns only a fixed 1280×720 PNG, and tears down in all outcomes. It must not return HTML, scraped text or OCR. Logs include hostname, duration/status/error type, not full URLs, content or screenshots.

Both cache reads and rendering require active owned run access, a claimed invitation bound to the visitor and a pending source decision. Check eligibility before I/O, after response and atomically before caching. Cache by source with bounded bytes and server TTL defaulting to one hour; expired entries count as absent, oversized screenshots may be returned without caching, and accepting/rejecting a source purges its preview. Cache hits issue no render call. Limit render attempts to two per visitor/run/source per 30 seconds. Cached screenshots remain outside every evidence and analytical path.

Chromium egress passes through a per-render authenticated loopback CONNECT proxy connecting only to a validated numeric public address. TLS remains end-to-end. Pause redirect responses and validate each destination, with the same five-hop limit and boundary for subresources. Block service workers, WebSockets, downloads and non-GET browser requests. Bound context lifetime, queue/concurrency, proxy connections and aggregate transfer. The independently packaged service preserves parity with backend private-address/redirect policy; a local correction is not evidence of remote deployment.
