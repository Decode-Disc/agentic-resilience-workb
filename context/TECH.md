# Technical Contract

## Authority and Boundaries

This document owns the current architecture, persistence, workflow, provenance, provider and security contracts. [PRODUCT.md](../PRODUCT.md) owns analyst behavior and acceptance, [AGENTS.md](../AGENTS.md) owns working and verification instructions, and the [roadmap](../docs/ROADMAP.md) separates delivery, dated verification and activation. Contracts for unfinished stages remain requirements, not claims of implementation. Historical ADRs preserve rationale without adding obligations outside these references. Discover actual implementation locations through repository exploration rather than maintaining code or test links here.

TanStack Start owns the web/SSR layer, with strict TypeScript, React and shadcn. Convex owns domain policy, structured persistence, reactive updates, artifacts, audit events and quotas. Convex Workflow is the single durable orchestration engine, including human waits, retries, cancellation and recovery. Vercel AI SDK supports typed provider adapters. Native Convex search owns derived retrieval; optional hosted embeddings do not introduce another state owner.

Keep domain records, persistence, orchestration, acquisition/normalization, model routing, analytical policy and UI projections distinct. UI components and SSR functions do not own evidence policy. Provider-specific SDK types and model identifiers stay behind adapters and configuration. CIK is canonical company identity; ticker, legal name, exchange and provider metadata are mutable. Retry, association and deduplication identity cannot depend on mutable labels unless a deterministic fixture explicitly owns them.

No second workflow engine, PostgreSQL, separate object store or custom realtime transport is part of the baseline. Eve and Vercel Workflow remain alternatives requiring demonstrated need and an explicit decision. Vercel Hobby is an acceptable hosting option only when its verified limits support the prototype; the technical baseline does not promise a free deployment. Model routes, access credentials, resource configuration, showcase identity and deployment URLs remain configuration data.

## Domain and Persistence

| Records | Ownership and invariants |
| --- | --- |
| `Visitor`, `Invitation`, `Company`, `ResearchRun` | Stable admitted identity, compatible access-slot storage, canonical company identity and revision-aware execution. |
| `ResearchPlan`, `ResearchPlanQuestion` | Versioned plan and immutable questions, each with a stable key, bounded text, dimension, template version and creation provenance. Coverage is derived, not written back into questions. |
| `Source`, `CorpusRevision`, `SourceDecision` | Candidate provenance, immutable approved membership and append-only analyst choices. Multiple edits may share a draft. |
| `SourceSelectionProposal`, `SourceSelectionProposalItem` | Immutable recommendation snapshot, policy/input identity, disposition, reasons and pinned preparation. No analyst decision is created by generation. |
| `SourceCapture`, `SourceVersion`, `SourcePassage` | Immutable prepared content, approved analytical representation and exact reproducible quotations. Preparation does not confer analytical authority. |
| `Claim`, `ClaimEvidence`, `ClaimDimensionLink` | Atomic canonical proposal, sole claim-to-passage relation, and separate claim-revision-to-dimension proposal. No effective analyst decision or final confidence lives in a generated proposal. |
| `ClaimDecision`, `ClaimDimensionDecision`, `AssessmentDecision` | Append-only decisions on claims, links and atomic dimension outputs, including justified overrides. |
| `AssessmentDimension`, `ScoreProposal`, `Relationship`, `BriefRevision` | Dimension proposals and versioned derived outputs subject to the product's approved-evidence constraints. |
| `AITaskResult`, `PolicyEvaluation`, `ProviderCall` | Typed versioned inputs/results, deterministic gate rationale and actual external-attempt telemetry. |
| `WorkflowStep`, `CheckpointDecision`, `RunEvent`, `AuditEvent` | Durable execution/checkpoints, product progress, and separate security/access/quota history. |
| `EvidenceSourceStatus`, `ArtifactUploadLease` | Mutable execution projection and artifact-upload lifecycle; neither replaces immutable evidence. |

Persisted and external data require runtime validation and closed lifecycle values. Preserve corpus, source, claim, link, assessment, map and brief revisions. Later additions cannot silently mutate prior results. Introduce final-model concepts only when observable behavior requires them.

A `SourceVersion` stores the canonical retrieval URL, content hash, media type, byte/page counts, retrieval/normalizer versions, metadata and normalized artifact storage identity. Changed fetched content creates another version; the same logical operation/hash reuses its result. Each `SourcePassage` belongs to one version, with exact quotation, normalized quotation hash, stable order and typed web/PDF locator. A quotation that cannot be reproduced from that version is structurally invalid.

`ClaimEvidence` alone assigns `supporting`, `counter` or `context`; discovery category, recommendation, source family and company linkage never pre-assign that relationship. `ClaimDimensionLink` binds one claim revision, dimension and extraction/corpus revision with `generated` or `analyst` origin, bounded rationale and the generating task when applicable. Every `Unknown` references an unresolved research-plan question and a context passage. Question backfills are protected, paginated and idempotent, using persisted company identity, dimension keys and bounded angle without changing the original plan or inventing provider-derived questions.

`EvidenceSourceStatus` is scoped to the frozen accepted source and execution generation, with `queued`, `running`, `succeeded`, `partial` or `failed`, bounded reasons and counts. `sourceReviewItems` is a derived source/revision projection maintained transactionally with decisions, and reconstructible through an idempotent administrative backfill. Summaries use bounded indexed reads, collection pages use native cursor pagination, and approval verifies authoritative effective decision heads rather than trusting historical accepted rows.

Protected source-review navigation uses validated `view` and `coverage` search parameters under `section=sources`: absent `view` means overview, `adjust` opens adjustment and `inspect` opens candidate inspection. Accept a canonical coverage-role key only during inspection. Showing all candidates removes `coverage`; returning to the overview removes both parameters. Refresh, direct links and browser history restore context without triggering discovery, decisions or approval. Standalone illustrative consumers retain local navigation through the existing component interface. Overview membership/counts and adjustment use the same bounded decision projection.

Large artifacts live in Convex File Storage. An upload lease records `reserved`, `uploaded`, `committed` or `orphaned`, attaching the storage ID as soon as available. Upload and database commit are not atomic: require one committed referenced artifact per logical operation, not zero transient uploads. Failed finalization marks an orphan and attempts deletion. Protected paginated cleanup reconciles old leases and storage after a safety interval, covering crashes before lease attachment and protecting both preparation captures and analytical versions.

## Workflow and Revision Contract

```text
Explicit company selection → preflight confirmation → atomic analysis reservation
→ authoritative identity revalidation → public-evidence sufficiency review when needed
→ research plan → discovery → bounded capture/qualification/comparison
→ inspect alternatives and one finite supplement → source proposal → corpus approval
→ exact approved materialization → analytical claims → structural/policy validation
→ counter-evidence within approved corpus → dimension review → derived views
→ finalization after all ten dimension decisions
```

| State family | Values |
| --- | --- |
| Research lifecycle | `draft`, `checking_public_evidence`, `awaiting_evidence_sufficiency_review`, `discovering_sources`, `awaiting_source_review`, `corpus_approved`, `extracting_evidence`, `evidence_ready`, `assessing_dimensions`, `awaiting_assessment_review`, `completed`. |
| Execution | `idle`, `running`, `paused`, `failed`, `cancelled`, `completed`. |
| Workflow step | `queued`, `running`, `completed`, `needs_review`, `failed`, `skipped`. |
| Completion outcome | `completed_assessment` or `insufficient_public_evidence`. |

Enforce transitions server-side. Execution status is separate from analytical lifecycle; failures and cancellation cannot invent analytical stages. A pause identifies the source/assessment checkpoint or the technical `claim_generation_unavailable` condition. Persisted `RunEvent` records alone drive product progress.

Preparation is opt-in through `SOURCE_QUALIFICATION_ENABLED=true`. New workflows snapshot an optional `prepareSources` argument; absent arguments retain the historical discovery-to-review sequence. Public preparation starts reject while disabled. Legacy refresh is explicit, never a page-render side effect. Preparation may retain its own handle alongside a legacy main workflow waiting for approval, on the same workflow engine. Activation remains subject to the bounded model and protected-journey acceptance recorded in the roadmap.

An editable draft accepts several additions and decisions. Approved membership is immutable; a change creates another draft and approval checkpoint. Unchanged captures and exact-input qualifications can be reused, but this does not promise complete incremental recomputation of downstream claims or briefs. New draft proposals use the persisted run pointing at that revision, not a stale prior-revision snapshot.

Approval and analytical start are one atomic handoff: verify ownership, approved revision, expected generation and visitor capacity; freeze the latest accepted decision heads and their authoritative IDs; claim the execution slot; advance generation; start the separate analytical workflow with a revision-bound idempotency key. Sources whose accepted decisions were superseded by pending/rejected heads confer no authority. Historical `corpus_approved + idle` dossiers retain the protected start operation. A reopened legacy corpus without a waiting discovery workflow uses this same evidence-execution owner. Emit extraction progress only after start. Sources remain inspectable read-only during and after extraction.

Store an active workflow ID only while execution runs. Completion compare-and-clears its own handle, never a newer execution. Every retryable operation binds run, workflow version, generation, corpus revision, step and attempt. Any resume that can become running atomically claims the visitor's single slot and advances generation. Check ownership, operation lease, generation and cancellation before I/O and again before persistence. Stale, duplicate or cancelled work cannot advance state or trigger another paid attempt. Retries do not duplicate evidence, reservations, call records or side effects.

`evidence_ready + idle` requires terminal frozen source branches, at least one structurally valid reproducible passage, a terminal claim pipeline and at least one valid claim visible in the matrix. Individual source failures and visible `needs_review`/`blocked` policy outcomes do not by themselves prevent that handoff.

If a live dossier has passages but no claim adapter authorized for their hashes, pause at `extracting_evidence + paused + claim_generation_unavailable`, set the claim step to `needs_review`, and release execution and the visitor slot. Do not fabricate `Unknown`, success or assessment access. Owner/administrator retry first checks capability; if unavailable, change no state or generation, claim no slot and issue no call. A valid retry claims the slot, advances generation and starts a current-version workflow scheduling only incomplete claim/policy steps from persisted artifacts. Cancellation prevents retry until explicit resume reclaims the run.

## Source Preparation and Selection

### Captures and qualification

Capture the exact normalized representation before qualification. Identity includes source, requested/resolved URLs, retrieval time, stored representation, content hash and retrieval/normalization versions. References bind exact quotations and offsets to those bytes. Pin captures and references on proposals. After approval, validate accepted-decision authority, hashes and locators and reuse those exact artifacts; missing/corrupt content fails explicitly without substitute retrieval.

Whole-capture storage, derived search candidates, selected model input and analytical passages are distinct artifacts. The analytical passage limit does not delete the retained capture, but storage alone does not prove downstream reachability of unselected content. Required qualification references and primary references from applicable pinned comparisons survive materialization or cause an explicit failure. Resolve comparison applicability through the shared source-use policy and retain only accepted sources in the approved revision. Verify required quotations against captured bytes and persisted passages before reuse; incomplete historical materializations are reported without rewriting them. Public PDF preparation uses Exa text and representation-relative locators; page-aware parsing remains a separate contract.

Typed qualification records purpose, company relationship, period, forecasts, attributed arguments, asserted facts and observed outcomes with reproducible references. Authority remains deterministic. Preserve restricted use and distinguish unavailable reading from irrelevance. Factual authority/corroboration excludes contextual, opposing and restricted argument citations. Required factual verification that is unavailable stays blocked or unknown.

Qualification protocol 3 uses one grouped call within fifteen findings. A documentary role is absent or has at most two homogeneous contributions, each with kind, period, dependency and at most three exact inspected references. Mixed/uncertain content has explicit use restrictions. The reading projection, claim creation and policy evaluation use the same finding-use rule. Ambiguous attributed hypotheses identify the intended contribution. Protocol-2 captures and approved pins remain readable; cached responses retain their original input identities. New captures pin their qualification-input policy. When all structured passages and their response schema fit the 128 KiB input allowance, selection uses the whole available document without native indexing or search; otherwise it retains retrieved passage selection. Selection strategy participates in input identity and persisted provenance. Partial captures remain partial. Historical captures preserve their original policy, including unknown provider outcomes.

New preparations snapshot `inline_controls_v2`, retaining the collect-then-compare order introduced by `collect_then_compare_v1`: finish capture/qualification and permitted supplementation before comparing against the resulting eligible primary captures and publishing. Absent snapshots retain the historical durable step sequence. Supplement planning shares the source classifier's identity, period, purpose, authority and independence rules but projects documentary presence separately from use restrictions; a pending comparison alone is not a gap, and rejected sources cannot satisfy this projection. Persist completion of the initial reading pass alongside its progress event and preserve that milestone across supplementation and recovery. The review projection distinguishes this milestone, current work and publication of the proposal; later reading batches do not restart the initial stage. Inspect existing non-rejected alternatives before one dossier-wide supplement. Supplemental content is read before the final comparison pass so later primary documents can inform earlier contributions. Explicit recovery creates a new fifteen-minute execution window without restarting the supplement or resetting cumulative counters. Availability is `available`, `limited` or `not established`, with a reason.

The protected review preparation mutation accepts a current metadata-only draft without requiring a stale proposal. Its query exposes start/resume availability without starting work. Prepared targeted searches use the same supplement ledger, with at most one search per explicit request. Claimed search indexes are immutable and shared across automatic and explicit searches. Topic-specific search results remain visible separately from the allowance for subsequent searches, including the last permitted search. Starting, resuming or targeting cannot create another supplement, replenish consumed search calls or bypass the atomic visitor execution slot. Missing configuration and exhausted allowances remain typed blocked outcomes.

Preparation checks current Node invocation configuration before acquiring content; activation and model credentials are read from `process.env` at invocation rather than the generated module-level environment snapshot. The review projection combines pinned qualifications, committed captures and recent operation outcomes, so a later targeted search cannot replace the dossier's preparation totals. Draft review exposes completed qualification outcomes immediately through the same capture/task/hash validation as published pins. Its inspection metadata, documentary roles and uses come from that same qualification through the existing source classifier; approved review resolves only its immutable proposal pins. Aggregate status reflects currently unresolved, non-rejected readings, and interruption reasons come from operations affecting those readings, including later manual additions. Metadata-only review omits capture projection reads, and source details reuse the validated qualification. Missing configuration before acquisition is unprocessed; retained content without a valid qualification is assessment unavailable. Query availability and mutation enforcement share recovery eligibility. An expired operation no longer prevents a new explicit recovery, while expiry still stops its own I/O and persistence. Resuming a targeted operation with new sources retains its narrow scope; a search with no additions cannot trap the original unfinished preparation in an empty scope.

Explicit regulatory coverage searches select the requested SEC form family through the confirmed company CIK; web coverage searches retain Exa. Each prepared search uses one shared ledger reservation, at most four candidates and the active execution deadline. A fully successful recovery clears only the searched discovery family, including when no new candidate was returned; partial or failed responses retain that family. Later explicit recovery therefore advances to remaining failures without resetting the ledger. The SEC adapter explicitly limits this path to one attempt and preserves transient HTTP/timeout errors as transport unavailability; its other callers retain their existing bounded retry policy. SEC transport reuses public-address validation and the pinned HTTPS requester with authorization before DNS, after DNS and before persistence, bounded timeout, byte limit and cancellation; redirects are not followed. Initial and targeted SEC discovery share document identity/provenance mapping. Coverage projects eligible or declared roles and document-type matches separately from other documents in the same family; inclusion alone cannot promote a candidate to established coverage.

Targeted additions carry their originating review operation and remain pending outside automatic recommendations until analyst inclusion. Duplicate resolution cannot let a review-only addition displace an existing recommendation. Only newly added IDs enter that operation's retrieval and qualification scope. After new content arrives, comparison may reuse exact earlier proposal pins for non-rejected sources under the same revision and execution fences, without granting retrieval or qualification authority over those older sources. No new primary result can clear earlier comparison issues silently.

A genuinely new manual source has a separate reading window for new content only. It cannot reopen older retrieval/qualification, reset dossier limits or add another supplement. Links received while another dossier runs are grouped; their window starts when the execution slot is claimed; an explicit recovery creates a new window for the same narrow scope. Intake request identity is independent of execution generation, and authenticated replay lookup precedes the paused-state check so a completed intake remains replayable after automatic preparation starts. Captures and qualifications are reusable only for matching logical inputs and versions. Preserve original paragraph identities/offsets and input omissions; descriptive prose, tables and examples take precedence over navigation when input space is full, without acquiring factual authority from formatting.

### Targeted comparison

Compare grouped eligible arguments and forecasts from a capture against relevant primary passages already captured for the same run and eligible under the active revision. Older captures may support comparison of new manual content without being requalified. Keep raw qualification and comparison results separate. Persist exact target and primary capture identities, hashes, spans and quotations, plus omissions and completeness.

Comparison reuse before input reconstruction requires a matching versioned preparation identity covering instructions, response schema, selection and retrieval policy, capture metadata and current index state. Revalidate authority, stored references, captured hashes and cited quotations before reuse; confirm the context again transactionally. Historical identities retain exact-input revalidation before adopting the new derived checkpoint. Captures without eligible contributions retain an idempotent local not-run result without retrieval or model work. Share immutable reads and validated comparison reviews only within one transaction, keeping approved pins distinct from recent draft qualifications.

`No conflict observed` requires comparable primary references and applies only to selected passages. Possible conflict or inconclusive results restrict affected automatic arguments without asserting a proven error. Match later issues by target capture/hash and overlapping span. New positive output cannot silently clear earlier issues. Pin comparison status and applicable issue history into proposal fingerprints and approval. Missing or stale checks never grant new attributed-hypothesis permission; independent useful contributions retain their permitted use.

Compact primary-reference aliases resolve only against the exact prepared input and preserve full identity in persisted results. All primary passages supplied in a grouped request are citable by every contribution in that request. Per-finding shortlists suggest retrieval relevance, not a second authority boundary. Reject foreign or omitted reference keys; keep per-result citation bounds. Alias/input changes alter cache identity without rewriting historical outputs.

Versioned retrieval promotes a covering quotation at the best rank of its contained units, then fills spare context from retrieved passages. The softer expansion allowance includes response-schema bytes and cannot remove existing priority context. Hard passage/request limits still apply. Unversioned inputs retain their previous selection. Preserve complete non-empty comparison explanations within the shared token and output-byte bounds, without an editorial character limit or output-repair calls. The response schema participates in input identity, so widening its explanation constraint changes new request hashes while historical comparison records remain readable without migration.

### Scoped retrieval

New preparations can snapshot `structured-v1` with `lexical` or `hybrid` retrieval. Absent configuration preserves the historical path. Derived capture, passage and embedding-cache records remain preparation artifacts. Convex owns native text search and a 1024-dimensional vector index. Search scope binds active run, revision, capture hash and policy; the cache binds exact searchable text and opaque embedding-profile version.

Parsing beyond the block/unit limits returns explicit unavailability before index writes. Eligibility is applied before native search limits and rechecked during hydration. Lexical queries read capture-scoped hits, combine ranks through reciprocal-rank fusion and retain bounded per-query results. Actions prefetch at most two internal search queries, each scoped to at most two captures with 64 hits per capture, and consume ordered results without retaining all query/capture combinations. Vector queries prefilter the composite run/revision/retrieval-version/profile/capture key. Vectors with older scope keys explicitly degrade to lexical until reindexing relinks exact-text cache entries; this neither changes models nor authorizes embedding calls. Historical prepared inputs remain unchanged.

Approved saved-source search uses the same derived capture index under separate approved-read authority. Public `ensureApprovedSourceIndex` and `searchApprovedSource` accept run, revision and source identifiers; the server resolves the exact approved capture. Authorize ownership and accepted revision membership before storage access, every index batch and completion. Index identity remains run/revision/capture/hash/retrieval version, completion is published only after all batches, and retries reuse exact rows. This read path does not require an active preparation or resume workflow execution. Missing, corrupt, legacy-without-capture and incomplete-index states remain explicit. No provider retrieval, model or embedding call is authorized by this interface.

The source-details search is lexical, debounced and bounded to 512 characters, 16 terms and 64 results. It retains the capture parsing/byte limits and returns source/capture/revision identity, content hash, retrieval time, exact quotation, quotation hash and offsets. Search candidates do not become analytical passages or claims automatically. Analyst copy shows context, quotations and availability without internal identifiers. Existing analytical limits of 512 passages per source and 4,096 per claim input remain unchanged. Materialization follows the pinned qualification extraction version; unversioned qualifications retain their original paragraph identities while reserving required references inside the same passage limit.

Workers AI is an optional direct adapter. `SOURCE_RETRIEVAL_MODE` accepts `lexical` or `hybrid`; uncached embeddings require secure action-side `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_AI_TOKEN` configuration. No local embedding model, Worker deployment, Vectorize index, new subscription or additional persistence owner is required by this design. Snapshot configuration only into new preparations.

Missing configuration or partial embeddings degrade explicitly to lexical with internal requested/effective modes and a reason. No truncation, redirects or automatic retries are permitted. The cumulative submitted-byte allowance conservatively bounds embedding usage at the accepted price ceiling, using one token per UTF-8 byte. Unknown outcomes retain their allowance. Historical evaluation allowances do not renew themselves or authorize activation.

### Deterministic proposals and legacy compatibility

Presets `balanced`, `first_party_depth` and `independent_scrutiny` adjust priorities and budgets only. An immutable proposal records active draft, policy version, candidate fingerprint, recommendation ceiling, disposition, rank and reasons. Proposal items may pin a versioned selection rationale distinguishing inspected contributions from discovery metadata. Legacy items remain readable without it; authorized draft recomputation records a new rationale from saved inputs without external I/O or rewriting approved proposals. `recommended`, `needs_attention` and `alternative` are system recommendations, not source decisions. Only reliable distinct contributions are added; the discovered recommendation ceiling is not a fill target.

Legacy metadata linkage is `structural`, `discovery_metadata`, `unverified` or `not_evaluated`. Structural checks use confirmed CIK, official domain, or approved decoded-path domain/complete legal-name sequences. Never derive structural linkage from query parameters, partial/generic legal-name tokens or ticker-only matches. For declared institutional publishers/shared IR hosts only, discovery titles may match the complete normalized legal name or an exact confirmed domain alias token of at least five characters. That metadata may support recommendation, never structural identity, document kind, duplication, evidence or automatic coverage. Analyst/historical items use `not_evaluated` rather than invented linkage proof.

Persist declared publisher capabilities separately from candidate-eligible coverage roles. Metadata-only non-structural candidates have no eligible roles. Prepared inspected content can establish relevance/purpose without promoting publisher authority. Classification uses authority-compatible explicit decoded URL-path tokens, structured SEC form/accession, period/event identity and confirmed domain, not arbitrary URL substrings or titles. Institutional publishers retain their declared independent/news roles; partners cannot satisfy first-party roles. Unverified company-matched counter-evidence leads remain inspectable alternatives. Reseller terms are corroborative review material, not canonical commercial terms.

Canonical/metadata-proven duplicates require stable identity. Preserve analyst references; cover required roles, then distinct periods, events, producers or angle contributions. Metadata recommendation contributions remain separate from coverage; old items hydrate an empty recommendation list without reinterpretation. Version-13 selection preserves metadata-established identity and distinct recommendation utility when reading is unavailable or partial without a documented contrary finding. Such retention grants no content coverage or factual authority, and its recommendation reason does not claim additional verified coverage. Valid analyst references, periodic-document novelty, and multiple qualified ordinary roles from one document remain supported. Independent-perspective roles still require distinct producers. Located caveats restrict their contribution/dependencies; unlocated caveats remain global. Draft v10/v11/v12 refresh uses saved candidates/qualification without discovery, provider calls or rewritten decisions. Other legacy migrations retain their existing behavior.

Ordering preserves authority, provider order, recency and research-angle precedence, then canonical URL before database identity. Recreating identical records cannot change which distinct documents are recommended. Analyst references are included before and outside the discovered recommendation ceiling. Attention/coverage gaps remain non-blocking; approval requires an accepted source, fresh proposal, integrity and authorization.

Include/remove/undo append accepted/rejected/superseding-pending decisions. Group approval atomically revalidates ownership, generation, draft, policy, proposal version and fingerprint; preserves overrides; accepts still-pending recommendations individually; leaves other candidates pending; records approval/audit and resumes execution. Candidate/policy changes mark drafts stale; older policy drafts require explicit rebuild. Approved revisions remain immutable.

Rebuild has a durable run/revision/generation/proposal/policy lease, serializes external work, checks the current pointer before dispatch and persistence, and returns `complete`, `partial` or `blocked` with affected search families. Partial results remain reviewable. Blocked results preserve the prior draft/decisions and allow a new fenced retry cycle after persisted cooldown. Current-policy recovery retries failed discovery families or searches one unconfirmed coverage role. It binds a stable request identity and target, preserves terminal replay, rejects expired-request redispatch and fences against approval, cancellation, supersession and lease expiry. It stays at the human checkpoint and performs metadata-only search. Refresh preserves failure records until actual recovery resolves them. Coverage is a bounded projection of effective inclusion and immutable eligibility, never a new decision authority.

## Acquisition, Validation and Providers

### Public URL intake and analytical materialization

All analyst URLs pass through one public intake owner before or after launch. Authorize target and applicable limits before DNS/HTTP. Pre-launch metadata inspection creates a short-lived owned receipt, not a source or evidence. Launch consumes valid receipt IDs atomically with initial pending sources; missing, expired, foreign or invalid receipts create no run or quota consumption. Active-run persistence atomically creates source, pending decision, review projection and audit after rechecking revision/generation.

Canonicalize public HTTPS URLs; reject credentials, unsupported ports/schemes and fragments as identity authority. Reject private, loopback, link-local, reserved and metadata destinations. Validate every redirect and connect to the numeric public address validated, preserving original HTTP Host/TLS SNI. Bound content type, transfer, decompression and time. Intake retries timeout, connection, upstream rate-limit or unavailable outcomes once, never deterministic validation, authorization, duplicate, capacity, unsupported-content or other client failures. Stable structured error codes define retryability and safe presentation.

Prepared analytical materialization validates exact captured bytes and required pins under accepted-decision authority. Legacy approved sources without pins use real SEC direct HTTP for confirmed CIK/accession and Exa Contents for general-web content. A web passage needs anchored text/section; a page-aware PDF locator needs its page and bounding text. Unreproducible passages are rejected. Frozen fan-out is the actual accepted-source count, not the recommendation ceiling. Partial source failures remain explicit and do not terminate unrelated branches.

The real Unstructured page-aware normalizer and general live analytical model adapters remain unfinished delivery work. Their intended interfaces are not permission to present fixtures as live. Deterministic claim/policy execution requires a complete normalized-input match to the approved fixture manifest, records `showcase` provenance, and creates no fictitious provider-call record. Arbitrary live inputs retain the workflow's explicit capability-unavailable stop.

### Typed analytical tasks and policy

Workflow requests capabilities, not models: source relevance, claim extraction, contradiction search, entailment, contradiction verification, dimension relevance, claim correction, dimension assessment and brief generation. Deterministic source composition does not call source relevance. Qualification/comparison are separate preparation tasks; their output cannot own inclusion or analyst authority.

Each task has versioned application-owned input/output schemas. Generated results cannot set approved status, final confidence, quality or workflow permission. Non-overridable structural checks enforce schema, approved membership, provenance and locators. Code-defined versioned policy combines observable evidence and selectively triggered, separately recorded semantic-verifier labels into `pass`, `needs_review` or `blocked` with explicit reasons. It does not verify every result with another model by default. Persist normalized inputs, executed rules, verifier references and outcomes. Policy changes create explicit evaluation revisions, never rewrite history. Product assessment outputs and justified overrides are governed by the product contract, with structural failures remaining non-overridable.

### Provider boundaries

The application-owned model router selects capability/quality/cost/availability and failure-aware routes. Required boundaries remain OpenRouter and experimental Codex subscription access, with a future-provider extension contract. Use Vercel AI SDK's OpenRouter adapter for OpenRouter and its OpenAI-compatible adapter only for private CLIProxyAPI inference. Never route OpenRouter through CLIProxyAPI or substitute API-key billing for the subscription option.

CLIProxyAPI uses the upstream distribution pinned to an immutable release/digest; the local fork is a behavioral reference, not a deployment artifact. Start with one instance/account unless measured need justifies expansion. Expose only authenticated inference, keeping management and subscription credentials private. Record upstream version and available usage without inventing subscription dollar cost. This prototype transport is neither official OpenAI integration nor a permanent-production commitment; its production readiness is not a candidature gate.

SEC uses identifying direct HTTP and a shared aggregate limiter below the SEC maximum. Exa discovery is metadata-only; HTTP searches omit `contents`. Exa Contents is separately authorized for preparation or legacy approved retrieval. Its text request respects the provider's 1,000,000-character bound and the application's byte bounds. The selected Unstructured integration is direct Pipeline Jobs HTTP, not the legacy Partition client.

Configuration owns primary route, allowed fallback, hard limits and retry policy. Provider-internal routing may preserve the configured model under explicit privacy/parameter constraints, but cannot silently change model, task semantics or authority. Persist logical operation/idempotency before I/O. Each retry/fallback has its own provider-call record with capability, task/prompt/schema versions, exact input/output references, resolved route, attempt, latency, usage, available reported cost and typed outcome. Do not record secrets or hidden reasoning. Missing configuration, disabled work and availability failures are explicit blocked/reviewable outcomes, not empty success.

Preparation disables automatic SDK/workflow model retries, permits a primary plus one technical fallback initially, and preserves structured-output and route-price ceilings. Each explicit recovery permits one additional attempt per operation and exact logical input after confirmed transient HTTP failure or a received invalid model output. Further explicit recoveries remain admissible while the dossier allowances permit them. Each recovered input uses the configured primary route without fallback; never-dispatched inputs retain their initial primary and one fallback policy. Valid uncertainty, missing configuration, cancellation, disabled paid work and account billing errors do not trigger fallback. Comparison shares the preparation allowances, concurrency, telemetry and execution fences. New `inline_controls_v2` preparations use journaled inline control mutations; the first batch lookup, comparison-target reads and final proposal stay scheduled. At most three consecutive source-result saves run inline before a scheduled fourth save yields the transaction. Earlier journals retain their step sequence. Transaction/request payload bounds remain independent of source fan-out. Recovery eligibility distinguishes never-dispatched work, confirmed transient responses (HTTP 408, 429, 500, 502, 503 or 504), received invalid output, terminal failure and unknown outcome. Timeouts after dispatch, ambiguous disconnects and expired started receipts authorize no automatic or additional attempt. Historical generic transport errors remain unknown unless their receipts prove otherwise. Persist a minimum fifteen-second cooldown and respect a longer valid Retry-After. Attempt identity excludes generation, request and route position; reservations are atomic and never reset by recovery. Preparation acquisition permits two initial attempts plus one explicit admissible recovery attempt; other acquisition consumers and embeddings keep their existing policies. A failed supplemental query may be retried once using an unconsumed search-call reservation, never exceeding three cumulative calls. Configuration checks occur before I/O and are recorded on the preparation rather than as fictitious provider calls. Validate changed transport contracts deterministically before an explicitly authorized local trial. Assess fresh analytical usefulness across different companies and dossier types before claiming general preparation acceptance; synthetic annotation of old outputs cannot establish it. A recorded experiment never selects a runtime model or authorizes activation by itself. Deployment-scoped activation enables the existing preparation controls without starting existing drafts; the initial local trial uses structured lexical retrieval.

## Access, Resources and Security

### Admission and execution authority

Maintain exactly five stable access slots: one administrator and four analysts, persisted as `Invitation` for compatibility. Convex Auth anonymous sessions use reusable four-digit codes stored only as HMAC-SHA-256 digests with a server-only pepper. Consume attempts atomically before digest verification. Preparation accounting uses a versioned dossier summary of valid responses, confirmed incidents, unresolved reservations and cumulative dispatches, updated atomically with provider receipts. Before dispatch, reserve room in both possible outcome allowances and in the absolute dispatch ceiling. A structurally and reference-valid response consumes productive capacity; confirmed dispatched failures, including received invalid output, consume incident capacity. Neither establishes semantic correctness or zero monetary cost. Settle each receipt once, releasing the other reservation; proved non-dispatch releases both and its dispatch reservation. Unknown outcomes retain both reservations and cannot authorize repetition. Cached reuse and deterministic comparison revalidation consume no model capacity. Review eligibility and dispatch enforcement use the same policy.

`SOURCE_PREPARATION_WORK_LIMIT` and `SOURCE_PREPARATION_INCIDENT_LIMIT` default to 120 and 40. Read current invocation configuration at explicit execution start and persist its snapshot; reject non-positive or unsafe integer values and an unsafe sum. Running executions retain their snapshot. A later explicit start or recovery may adopt changed ceilings without resetting consumption; the absolute dispatch ceiling is their sum. Existing editable dossiers derive initial accounting from bounded historical receipts and the conservative maximum of legacy counters. Missing identity or unexplained consumption remains reserved. Initialize the summary once before dispatch without rewriting receipts or approved revisions; review uses the same historical interpretation without writing. Acquisition, supplement search and embedding allowances are separate and unchanged.

### External I/O and transient preview

Authorize every protected operation and applicable lease/generation before DNS, SDK or HTTP work. Revalidate before persistence. Apply least privilege, server-only secrets, safe logging, content sanitization and bounded parsing/decompression. Treat source text and model output as untrusted evidence, never system instructions. Defend against embedded prompt instructions and outbound SSRF, including redirects and DNS rebinding.

Visual preview uses a separately packaged Playwright service, behind an authorized Convex action, never direct browser-to-service traffic. The service accepts authenticated `POST /render`, creates a fresh context without prior cookies/storage/credentials/downloads, returns only a fixed 1280×720 PNG, and tears down in all outcomes. It must not return HTML, scraped text or OCR. Logs include hostname, duration/status/error type, not full URLs, content or screenshots.

Both cache reads and rendering require active owned run access, a claimed invitation bound to the visitor and a pending source decision. Check eligibility before I/O, after response and atomically before caching. Cache by source with bounded bytes and server TTL defaulting to one hour; expired entries count as absent, oversized screenshots may be returned without caching, and accepting/rejecting a source purges its preview. Cache hits issue no render call. Limit render attempts to two per visitor/run/source per 30 seconds. Cached screenshots remain outside every evidence and analytical path.

Chromium egress passes through a per-render authenticated loopback CONNECT proxy connecting only to a validated numeric public address. TLS remains end-to-end. Pause redirect responses and validate each destination, with the same five-hop limit and boundary for subresources. Block service workers, WebSockets, downloads and non-GET browser requests. Bound context lifetime, queue/concurrency, proxy connections and aggregate transfer. The independently packaged service preserves parity with backend private-address/redirect policy; a local correction is not evidence of remote deployment.
