# Isolated live framing-tool comparison

On 2026-11-20, twelve direct OpenRouter requests compared a state-projected `adjust_framing` with lifecycle-specific `create_framing` and `revise_framing`. GLM 5.3 Flash, high reasoning, temperature zero and Wafer routing were held constant. Three situations (initial creation, repair of the retained missing-anchor refusal, and revision preserving an existing scope/question) were repeated twice per interface. Generation took 17.332 seconds in concurrent waves of four and cost $0.002462964 according to returned usage. Preparation and local validation are additional time. No browser, application campaign, external research or paid reviewer was used; no requests were retried.

| Exercised criterion | Single operation | Separate tools |
| --- | --- | --- |
| Exactly one call to the offered tool, valid offered JSON schema | 6/6 | 6/6 |
| Initial open activity anchor, accepted persisted write | 2/2 | 2/2 |
| Missing-anchor repair, accepted persisted write | 2/2 | 2/2 |
| Requested revision accepted, prior scope/question preserved | 2/2 | 1/2 |

Every retained response was parsed against its offered JSON schema and the real production Convex input validator, then submitted through real operation enqueue/dispatch in an isolated convex-test dossier using definition version 7. The two hypothetical tool names were mapped to the existing `adjust_framing` operation for this check. This validates proposed arguments against the current business write owner, not implementation of new tool routing. The update fixture installed the stated preexisting framing before starting its turn. No production implementation or running backend was changed.

## Confirmed failure and interpretation

`update-split-1` called `revise_framing`, preserved the requested scope/question, and added a switching-cost question. It also introduced an open condition whose analyst basis quoted the old question rather than the active request. The business validator refused `eventBasis.conditions[0].basis.excerpt` with `framing_event_basis_invalid`. The persisted draft stayed at revision 1. See `result-update-split-1.json` and `validation-update-split-1.json`. The causal mechanism of the refusal is verified; attribution of this model choice to the tool name is not established.

The final local replay produced 11 passes and one genuine model-output failure in 4.82 seconds; that failure was retained, not weakened. The first validation pass incorrectly assumed question text was persisted byte-for-byte. The existing owner intentionally prefixes open conditional questions with their hypothesis (`convex/domain/framingProvenance.ts`). The assertion was corrected to permit that established transformation while checking persisted scope, question identities and retained submitted question text; exact preservation remains asserted for the update case. Both validation logs and the final executable source are retained. No additional model calls were made.

## Decision support and limits

Prefer the single existing operation with state-dependent requirements: the probe provides no reason to add separate lifecycle names, and the existing write path can be extended. This is a maintenance/design recommendation supported by the observed results, not a statistically demonstrated model superiority claim.

Paired requests differed only by tool name. Both interfaces received equivalent state-dependent descriptions and schemas, explicit activity-anchor guidance, the same inline framing skill, and only the currently applicable tool. This isolates naming under a simplified context; it does not compare a static universal schema against two specialized schemas, test selection between simultaneously offered tools, exercise schema refresh after a save, or replay the complete native mission. There is no uncorrected baseline arm and no causal claim that schema changes alone repair the original defect.

Accepted writes do not establish analytical correctness. In particular, the retained repair input already contained unsupported event-specific attributions; three repair responses retained those substantive flaws, while one single-operation response revised them. These responses count as successful missing-field repairs only. The initial responses also warrant separate semantic review of their hypotheses. This probe does not qualify documentary usefulness, provenance entailment or overall agent reliability.
