## Verdict: Changes Required

Three medium-severity findings remain: two blocking functional defects and one nonblocking acceptance-evidence gap. Oracle reports BLOCK because a conversation page can overrun the read budget when it contains several individually valid large replies. Code Reviewer reports REQUEST CHANGES because purge can miss payloads after its first parent batch; it also retains a performance-evidence WATCH. Severity and acceptance impact are reported separately.

### Conversation page hydration exceeds capacity for several large replies

**Reported by Oracle; medium, blocking; source-derived, not reproduced.** [readConversationMessages](../../../convex/integrations/agentStorage.ts:47) combines all fragments for the selected deliveries into one component query. [Workbench history](../../../convex/workbench.ts:831) and [conversation listing](../../../convex/execution/conversations.ts:696) can each request 20 complete deliveries without selecting them by body size first. Installed Convex Agent stores both the original message content and extracted text and reads complete component records. Eight replies of 1,100,001 bytes therefore require at least 17,600,016 read bytes before metadata, exceeding 16 MiB; eight replies and their user messages fit in one page. Individual publication can succeed while reopening the saved conversation fails.

The existing large-response regression tests one large reply at a time. Correct page selection/hydration against actual capacity, preserve delivery identity/cursors and complete-text retrieval, and add a transaction-limit regression through both public readers with multiple valid large replies. Do not restore an aggregate generation-size ceiling. The parent independently inspected the shared reader, both callers and installed component storage/query code; no runtime reproduction was added.

### Purge does not advance beyond its first parent batch

**Reported by Code Reviewer; medium, blocking; source-confirmed, not reproduced.** [Invocation payload cleanup](../../../convex/dossierPurge.ts:317) repeatedly selects the first 100 parent invocations. After removing their payloads, it returns false without moving past those parents. The [purge action](../../../convex/dossierPurge.ts:615) then proceeds to later steps, eventually deleting all parent invocations and the dossier while later payloads/fragments remain. [Session cleanup](../../../convex/dossierPurge.ts:292) shares this traversal flaw. Later invocation deletion handles its own response/input references, not the skipped payload records.

This defect predates the extension but invalidates its claim of complete owned-payload cleanup. Traverse all parents with continuation, or remove parents only after their owned children, using the existing purge owner. Test at least 101 parents with owned data beyond the first batch, including the session sibling. The parent checked the traversal and action ordering. This finding is separate from the deliberately retained Convex Agent component/shared state acknowledged in the purge comment; that broader physical-erasure policy was not reopened.

### Projection and ancestry performance acceptance lacks retained-data evidence

**Reported by Code Reviewer; medium, nonblocking WATCH; evidence gap.** The [projection benchmark](../../../src/__tests__/convex/execution/research-state.test.ts:1103) uses a five-capture synthetic fixture generated by [researchState.ts](../../../convex/fixtures/researchState.ts:48), including repeated capture records and example.com sources. This is useful coverage of real query handlers but does not establish the retained-preparation before/after measurement or retained legacy cursor-ancestry cost required by the [approved TDD](29-tdd-sources-harness-efficiency.md).

The [implementation record](32-implementation-sources-harness-efficiency.md) closes the projection-cost watch too broadly. Preserve the synthetic measurements and label their limits; keep acceptance open until the specified bounded retained-data measurements exist. Real history-payload replay did run successfully in this review, but it is a different proof and does not close the projection or ancestry obligation. No current projection malfunction is established by this finding.
